## 적용 범위 — 컴포넌트를 두는 자리가 범위다

도는 동안에는 그 화면 전체(문서 전체)의 스크롤 영역을 다룬다. 그래서 어디에 두느냐(React 없이 쓸 때는 언제 설치하고 걷느냐)로 범위를 정한다.

| 범위 | 두는 자리 |
| --- | --- |
| 앱 전체 | 앱의 맨 위 레이아웃 |
| 특정 페이지(경로)만 | 그 페이지나 페이지 묶음의 레이아웃. 그 페이지에 있는 동안만 돌고, 떠나면 되돌린다 |

- **점진적 도입**: 한 페이지부터 켜 보고 넓혀 가는 것은 이것으로 한다.
- **공통 영역에도 적용된다**: 켜져 있는 동안에는 그 페이지의 본문뿐 아니라 같이 보이는 공통 영역(사이드바·머리글·모달)에도 적용된다. 켠 페이지와 안 켠 페이지를 오가면 공통 영역의 스크롤바 모습이 달라 보일 수 있다.
- **일부만 켜기는 없다**: 화면의 일부(컨테이너 하나)만 켜는 옵션은 아직 없다. 일부를 **빼는** 것은 `exclude` 로 한다.

## 옵션

모두 화면 전체에 거는 설정이다. 영역마다 다르게 하는 것은 [영역별 설정](#영역별-설정).

| 옵션 | 값 | 기본 | 뜻 |
| --- | --- | --- | --- |
| `stayClose` | 숫자(px) | `12` | 스크롤바를 바깥에 띄울 때 영역의 끝에서 떨어뜨려도 되는 거리의 한도 |
| `exclude` | CSS 선택자 문자열 | 없음 | 이 선택자에 걸린 요소와 그 아래는 건드리지 않는다 |
| `debug` | 참·거짓 | 거짓 | 진단 표시를 켠다 — 영역마다 무엇을 했는지를 화면에 그린다 |
| `quiet` | 참·거짓 | 참 | 브라우저가 남기는 「ResizeObserver loop」 알림을 가로챈다 |
| `textarea` | 참·거짓 | 거짓 | 입력창(`textarea`)도 본다 |

```tsx
<MrScroll stayClose={4} exclude=".some-widget, .third-party" textarea debug />
```

```ts
installMrScroll({ stayClose: 4, exclude: ".some-widget, .third-party", textarea: true, debug: true });
```

### `stayClose` — 바깥에 띄울 때 떨어져도 되는 거리

- **무엇을 재나**: 영역을 여백 없이 감싼 카드·틀의 테두리를 건너 바깥 여백에 띄우면, 건넌 테두리 두께의 합만큼 스크롤바가 영역에서 떨어진다.
- **넘으면**: 그 거리가 이 값을 넘으면 바깥에 띄우지 않고 내용 위에 겹친다.
- **기본값(12px)**: 흔한 테두리(1px 에서 4px)는 걸리지 않는다.
- **제한을 없애려면**: `Infinity` 를 준다.
- **적용되는 축**: 세로·가로에 같이 적용된다.
- **잘못된 값**: 음수나 숫자가 아닌 값은 기본값으로 친다.
- **오차**: 맞닿았는지를 1px 오차로 보므로 한도 근처에서는 1px 이나 2px 어긋날 수 있다.

### `exclude` — 건드리지 않을 구역

- **범위**: 선택자에 걸린 요소와 **그 아래 전부**의 스크롤 영역을 찾지도 건드리지도 않는다.
- **바깥 영역도 손대지 않는다**: 바깥 스크롤 영역이 자기 스크롤바를 받으려고 그 구역의 여백을 줄이는 일도 없다.
- **언제 쓰나**: 마크업에 `data-scrollbar="off"` 를 붙일 수 없는 외부 위젯을 빼는 데 쓴다.
- **여럿**: 쉼표로 여럿을 줄 수 있다.
- **틀린 선택자**: 없는 것으로 친다.

### `debug` — 진단 표시

손을 댄 스크롤 영역마다 화면 위에 겹쳐 그린다.

- 방식별 색의 테두리
- 스크롤바가 놓인 자리
- 줄이거나 더한 여백
- 스크롤바가 없을 때의 내용 자리
- 방식·스크롤바 굵기·바꾼 값·까닭을 적은 딱지

알아 둘 것:

- 같은 내용을 영역의 속성으로도 적는다.
- 스크롤 영역에는 아무것도 끼워 넣지 않고, 누름을 가로채지 않고, 판별 결과도 바꾸지 않는다.
- 켠 동안에는 영역들의 자리를 매 프레임 다시 재므로 개발 중에만 켠다.
- 보는 법은 [문제 해결](./troubleshooting.md#문제-해결)에 있다.

### `quiet` — 브라우저 알림 가로채기

- **왜 있나**: 스크롤바가 생긴 것을 알아챈 그 자리에서 여백을 고치기 때문에, 브라우저가 `ResizeObserver loop completed with undelivered notifications` 알림을 자주 남긴다. 동작에는 문제가 없지만 오류 수집 도구에 쌓인다.
- **기본(참)**: 이 알림을 가로채, 이 장치보다 나중에 등록된 리스너에 닿지 않게 한다.
- **주의**: **다른 코드가 낸 같은 알림도 같이 가려진다.**
- **끄려면**: 그 알림을 직접 보고 싶으면 `false` 를 준다.

### `textarea` — 입력창도 보기

- **기본(거짓)**: 입력창은 보지 않는다. 높이를 내용에 맞추는 코드와 얽히기 쉽기 때문이다.
- **켜면**: 다른 스크롤 영역과 같은 순서로 판별한다.
- **되는 것은 두 가지다**: 입력창에는 스크롤바를 띄울 수 없다(shadow root 를 붙일 수 없는 태그다).

| 입력창의 상태 | 결과 |
| --- | --- |
| 오른쪽 여백이 스크롤바 폭 이상이다 | 그 여백을 줄인다. 글자가 놓이는 폭이 그대로라 줄바꿈이 안 바뀐다 |
| 오른쪽 여백이 스크롤바보다 좁다 | 그대로 둔다. 글자가 스크롤바 폭만큼 밀린다 |
| 폭을 `box-sizing: content-box` 로 못박았다(브라우저 기본값) | 그대로 둔다. 여백을 줄여도 글자 폭이 늘지 않고 상자만 줄어들기 때문이다 |
| `data-scrollbar="manual"` 을 붙였다 | 폭(`--sbw`)을 받아 직접 맞춘다 |

- **받게 하려면**: 입력창의 좌우 여백을 스크롤바 폭 이상으로 주고, 폭을 숫자로 준 입력창에는 `box-sizing: border-box` 를 준다(대부분의 CSS 초기화는 이미 그렇게 해 둔다).
- **입력창의 크기는 바뀌지 않는다**: 폭·높이를 고쳐 쓰지 않는다.
- **자식으로 있는 입력창도 같다**: 옵션을 켜지 않으면, 다른 스크롤 영역을 꽉 채운 자식으로 있는 입력창의 여백도 건드리지 않는다.
- **늘 띄워 두는 스크롤바는 그대로 둔다**: `overflow: scroll` 인 입력창의 빈 스크롤바는 숨기지 않는다. 글이 바뀌어 넘치게 되는 것을 알아챌 수 없기 때문이다.
- **되돌리기**: 옵션을 끄거나 걷으면 원래 값으로 되돌린다.

### 여러 번 설치했을 때

- 가장 나중에 설치한 것의 옵션을 쓴다.
- 그것을 걷으면 그 앞의 것으로 돌아간다.
- 옵션이 바뀌면 보고 있던 영역을 전부 다시 판별한다.

## 영역별 설정

자동 판별이 맞지 않는 영역에는 스크롤 요소에 `data-scrollbar` 를 붙인다. 영역마다 주는 설정은 이것 하나다. 붙이지 않는 것이 기본이다.

| 값 | 동작 | 언제 쓰는가 |
| --- | --- | --- |
| `off` | 그 영역을 판별과 수정 대상에서 뺀다. 세로·가로 모두 원래 스크롤바 그대로다 | 장치가 건드리면 안 되는 영역 — 직접 스크롤바를 다루는 컴포넌트. 마크업에 손댈 수 없는 외부 위젯은 옵션 `exclude` 로 뺀다 |
| `center` | 좌우 빈 자리가 달라도 **가운데 정렬 방식(2번)으로 판별하게 한다** | 가운데 정렬인데 좌우 빈 자리가 2px 넘게 달라 자동 판별이 2번을 고르지 못한 영역 |
| `manual` | **직접 조절한다.** 세로 스크롤바 폭을 CSS 변수 `--sbw` 로, 가로 스크롤바 높이를 `--sbh` 로 내려 주기만 하고, 자동 판별은 하지 않는다. 그 값을 어디에 어떻게 쓸지는 화면 코드가 정한다 | 자동 판별 대신 여백을 직접 정하고 싶은 영역 — 행마다 여백이 있는 목록, 스크롤바와 내용 사이 간격을 따로 정하고 싶은 영역, 스크롤바를 띄울 수 없는 목록 태그·표·입력창(입력창은 `textarea` 옵션을 켜야 값이 온다) |

```html
<!-- 건드리지 않는다 -->
<div data-scrollbar="off" style="overflow-y: auto">…</div>

<!-- 2번 방식으로 고정한다 -->
<div data-scrollbar="center" style="overflow-y: auto">
  <article style="max-width: 720px; margin-left: 40px">…</article>
</div>
```

### `center` — 내용을 가운데로 옮겨 주는 설정이 아니다

- 판별을 2번 방식으로 고정하는 설정이다.
- 왼쪽에 스크롤바 폭만큼 여백을 더해, 이미 가운데 놓인 내용이 스크롤바가 생겨도 제자리에 있게 한다.
- 2번을 적용할 수 없는 구조(안쪽에 빈 자리가 없는 경우 등)면 3·4번으로 넘어가지 않고 아무것도 하지 않는다.
- 스크롤 영역 자신의 오른쪽 여백이 충분하면 1번이 먼저 적용된다.

### `manual` — 스크롤바 폭을 받아 직접 조절한다

자동 판별은 「장치가 알아서 고른다」이고, `manual` 은 「폭만 알려 줄 테니 직접 정하라」다.

- 이 설정을 붙인 영역에서는 원래 스크롤바가 그대로 뜬다. 장치는 가운데 정렬·바깥에 띄우기·겹치기를 하지 않는다.
- 장치가 하는 일은 그 영역에 값 두 개를 적어 주는 것뿐이다.
  - `--sbw` 는 세로 스크롤바의 폭, `--sbh` 는 가로 스크롤바의 높이다.
  - 스크롤바가 떠 있으면 그 굵기(예: `11px`), 없으면 `0px` 이다.
- 영역 안의 어느 요소든 `var(--sbw, 0px)`·`var(--sbh, 0px)` 로 그 값을 받을 수 있다. 행, 머리글 줄, 하단 버튼 줄 어디든 된다.

| 원하는 것 | 쓰는 식 | 결과 |
| --- | --- | --- |
| 내용이 밀리지 않게 한다 | `padding-right: calc(16px - var(--sbw, 0px))` | 여백이 스크롤바 폭만큼 줄어, 스크롤바가 생겨도 내용 자리가 같다 |
| 스크롤바와 내용 사이를 최소 8px 은 띄운다 | `padding-right: max(8px, calc(16px - var(--sbw, 0px)))` | 스크롤바가 굵어도 8px 은 떨어진다. 모자란 만큼은 내용이 밀린다 |
| 스크롤바가 있을 때 여백을 더 넉넉하게 둔다 | `padding-right: calc(24px - var(--sbw, 0px))` | 스크롤바가 없으면 24px, 있으면 내용과 스크롤바 사이가 `24px − 스크롤바 폭` 이다 |
| 스크롤 영역 밖의 줄을 스크롤바 폭에 맞춘다 | 값을 받을 요소가 영역 안에 있어야 한다 | 영역 밖 요소에는 값이 오지 않는다 |

```html
<ul data-scrollbar="manual" style="overflow-y: auto">
  <li style="padding-right: calc(16px - var(--sbw, 0px))">…</li>
</ul>
```

알아 둘 것:

| 상황 | 내용 |
| --- | --- |
| 밀리지 않으려면 | 「오른쪽 여백 + 스크롤바 폭」이 스크롤바 유무와 상관없이 같아야 한다. 표의 첫 줄이 그 식이다. 다르게 쓰면 그 차이만큼 밀리고, 그것은 쓰는 쪽의 선택이다 |
| 여백이 스크롤바보다 작으면 | 음수가 되어 그 선언이 무시된다. `max(0px, …)` 로 감싼다 |
| 1번(자기 여백)이 먼저다 | 스크롤 영역 자신의 오른쪽 여백이 스크롤바 폭 이상이면 장치가 그 여백을 줄이고 `--sbw` 는 0 이다 |
| 가로도 같다 | 스크롤 영역 자신의 아래 여백이 스크롤바 높이 이상이면 장치가 그 여백을 줄이고 `--sbh` 는 0 이다. 아니면 `--sbh` 로 높이를 내려 주고, 가로 스크롤바도 띄우지 않는다 |
| 가로 넘침이 세로 스크롤바 때문에만 생긴 경우 | `--sbh` 가 0 이다. 세로를 받으면 그 넘침이 같이 사라지기 때문이다 |
| 안쪽에 또 스크롤 영역이 있으면 | 그 안에서는 0 으로 끊긴다. 바깥 영역의 값이 안쪽으로 새지 않는다 |

## 적용 시 권장사항

### 좌우 여백은 같은 요소에 같은 값으로 준다

- `padding: 0 16px` 처럼 준다.
- 왼쪽 여백은 바깥 틀에, 오른쪽 여백은 스크롤 영역에 주면 눈에는 같아 보여도 판별이 갈린다.

### 스크롤바를 위해 오른쪽 여백을 따로 더하지 않는다

- `padding-right: 17px` 같은 값은 스크롤바용인지 디자인 여백인지 알 수 없어, 이 장치가 없애지 않는다.
- 스크롤바가 생길 때 밀리는 것은 보정하지만, 스크롤바가 없을 때 오른쪽이 넓어 보이는 것은 남는다.
- 그 값을 지우면 자동으로 맞는다.

### 스크롤바 자리를 미리 잡지 않는다

- 잡아 둔 것(`scrollbar-gutter`)은 가능한 경우에 풀어 준다.
- 그래도 처음부터 없는 편이 결과가 분명하다.

### 스크롤바 폭을 재서 여백을 고치는 자체 스크립트가 있으면 걷어 낸다

- 두 장치가 같은 여백을 다루게 된다.
- 이 장치가 원래 스크롤바를 숨긴 뒤에도 그 스크립트가 재 둔 값이 남아, 여백이 한 번 더 들어간다(시험에서 왼쪽 여백이 스크롤바 폭만큼 더 들어가는 것을 확인했다).
- 걷어 낼 수 없으면 그 영역에 `data-scrollbar="off"` 를 붙인다.
