## 하는 일 한눈에

| 하는 일 | 내용 |
| --- | --- |
| 자동 탐색 | 화면의 세로·가로 스크롤 영역을 계산된 스타일로 찾는다. class 이름이나 CSS 작성 방식에 기대지 않는다. 나중에 붙는 요소(모달·드롭다운)도 찾는다 |
| 영역별 판별 | 한 가지 보정을 모든 영역에 똑같이 적용하지 않는다. 영역의 구조를 보고 네 가지 방식 중 하나를 고른다([자동 판별의 우선순위](#자동-판별의-우선순위)) |
| 세로·가로를 따로 | 두 스크롤바의 자리를 각각 정한다 |
| 기본 스크롤바 유지 | 직접 그린 스크롤바가 아니라 브라우저 기본 스크롤바를 쓴다. `scrollbar-width`·`scrollbar-color`·`::-webkit-scrollbar` 로 꾸민 모양도 따라간다 |
| 스크롤바 폭을 재서 쓴다 | 폭을 가정하지 않고 그 브라우저에서 잰 값을 쓴다 |
| 다시 판별 | 영역·내용의 크기가 바뀌거나 요소·스타일이 바뀌면 다시 판별한다 |
| 원상복구 | 바꾼 여백·변수·표시를 요소마다 적어 두고, 장치가 내려가면 되돌린다. 스크롤바를 띄운 영역에 붙인 shadow root 만은 떼어 낼 수 없어 남는다([제약사항](./troubleshooting.md#제약사항)) |
| 겹친 영역 | 스크롤 영역 안에 스크롤 영역이 있으면 바깥 것부터 판별해, 같은 여백을 둘이 쓰지 않게 한다 |
| 설정 | 전체에 거는 옵션 다섯 가지(`stayClose`·`exclude`·`debug`·`quiet`·`textarea`)와, 영역마다 붙이는 `data-scrollbar`(끄기·방식 고정·직접 조절)가 있다. 아무것도 주지 않아도 동작한다 |
| 진단 표시 | 켜면 화면 위에 영역마다 무엇을 했는지를 그려 보여 준다: 고른 방식과 까닭, 스크롤바가 놓인 자리, 줄이거나 더한 여백의 전·후 값, 스크롤바가 없을 때의 내용 자리 |

## 자동 판별의 우선순위

이 장치의 핵심이다.

- 스크롤바를 한 가지 방법으로 보정하지 않는다.
- 스크롤바가 뜬 영역마다 구조를 분석해 **맞는 첫 번째 방식**을 쓴다.
- 아래에서 `S` 는 그 브라우저에서 잰 스크롤바 폭이다.

### 세로 스크롤바

| 순서 | 영역의 구조 | 하는 일 | 내용을 가리나 |
| --- | --- | --- | --- |
| 1 자기 여백 | 스크롤 영역 자신의 오른쪽 여백이 `S` 이상이다 | 그 여백을 `S` 만큼 줄인다. 스크롤바가 그 자리에 뜬다 | 아니오 |
| 2 가운데 정렬 | 안쪽 내용의 좌우 빈 자리가 같다(차이 2px 이하) | 왼쪽에 `S` 를 더한다 | 아니오 |
| 3 바깥 여백 | 스크롤 영역의 오른쪽 끝이 바깥 틀의 여백(`S` 이상)에 맞닿아 있거나, 오른쪽 바깥이 빈 자리다 | 스크롤 영역은 그대로 두고, 스크롤바만 영역 바로 밖에 띄운다 | 아니오 |
| 4 겹치기 | 위 셋이 다 안 된다 | 스크롤바를 내용의 오른쪽 끝 위에 띄운다 | 손잡이가 놓인 곳만, 반투명으로 |

### 방식별 세부

#### 1 자기 여백

- **왜 있는가**: 가장 흔한 구조다. 영역 안에서 끝나므로 바깥에 미치는 변화가 없다.

#### 2 가운데 정렬

- **왜 있는가**: 가운데 놓인 내용은 오른쪽만 줄이면 가운데가 틀어진다. 양쪽을 같게 해야 제자리에 있다.

#### 1 과 2 는 상자의 바깥 크기를 바꾸지 않는다

- 크기를 안쪽 내용 기준(`box-sizing: content-box`)으로 못박은 상자(`width: 240px` 처럼)는 여백만 줄이면 글자 칸은 그대로인 채 상자 전체가 줄어든다.
- 그런 상자에는 그 방식을 쓰지 않고 다음 순서로 넘어간다. 가로 스크롤바의 아래 여백(높이)도 같다.
- 폭·높이를 고쳐 써서 맞추지는 않는다. 비율로 준 크기가 숫자로 굳고, 내용으로 정해지는 크기를 못박게 되기 때문이다.
- 폭을 꽉 채운 안쪽 자식의 여백을 줄일 때도 같은 기준이다 — 줄여도 그 자식의 글자 칸이 스크롤바가 없을 때와 같지 않으면 쓰지 않는다.
- 판단하는 법: 스크롤바가 없을 때의 크기와, 여백을 바꾼 뒤의 크기를 재서 같은지 본다. `content-box` 상자에서만 잰다.

#### 3 바깥 여백

- **왜 있는가**: 여백이 스크롤 영역이 아니라 바깥 틀에 있는 구조(틀을 꽉 채운 목록)다. 줄일 여백이 영역에 없다.
- **테두리가 있는 상자에도 같다**: 바깥에 자리가 있으면 테두리 바로 밖에 띄운다.
- **감싼 틀은 몇 겹이든 지나간다**: 영역을 여백 없이 감싼 틀(사이에 다른 요소가 없고 테두리만 있다)이 그렇다.
- **너무 멀어지면 쓰지 않는다**: 건넌 테두리 두께의 합이 `stayClose`(기본 12px)를 넘으면 4 로 간다. 스크롤바가 자기 영역에서 떨어져 보이기 때문이다.

3 을 쓰지 않고 4 로 가는 경우:

| 경우 | 까닭 |
| --- | --- |
| 스크롤 영역 자신이 모양대로 오려 내거나(`clip-path`) 가림막(`mask` — 위아래 끝을 흐리게 하는 효과 등)을 씌웠다 | 영역 밖에 띄운 스크롤바가 영역 자신에 오려져 안 보인다 |
| 스크롤바가 놓일 자리에 다른 요소(여백 안에 띄워 둔 닫기 버튼 등)가 걸쳐 있다 | 띄운 스크롤바가 그 요소를 덮고 누름을 가로채지 않게 하려는 것이다 |

- 영역 전체를 덮는 배경·장식 층은 「그 자리에 놓인 요소」로 치지 않는다.

#### 4 겹치기

- **왜 있는가**: 행이 가장자리까지 찬 목록·격자처럼 어디에도 자리가 없는 구조다. 밀리는 대신 내용 위에 띄우는 쪽을 택한다.
- **여기로 오는 배치**: 자식을 위에서 아래로 쌓지 않는 배치(격자·가로 배치·거꾸로 쌓기)도 여기로 온다.
- **맨 마지막인 까닭**: 내용을 가리는 방식은 4 뿐이다.

4 도 스크롤바 폭 전체를 가리지는 않는다.

- 띄운 스크롤바는 배경(손잡이가 지나다니는 띠)이 투명하다.
- 손잡이 색을 따로 정해 두지 않았으면 손잡이도 반투명(검정 35%)이다.
- 그래서 가려지는 것은 손잡이가 놓인 부분뿐이고, 그 부분도 뒤 내용이 비쳐 보인다.
- 화면 코드에서 손잡이 색을 정해 뒀으면(`scrollbar-color`·`::-webkit-scrollbar-thumb`) 그 색을 그대로 쓴다.
- 다만 띄운 스크롤바가 놓인 자리의 클릭은 스크롤바가 받는다.

#### 3 과 4 는 스크롤바를 따로 띄운다

- 원래 스크롤바를 숨기고 같은 모양의 스크롤바를 따로 띄워, 두 스크롤 위치를 맞물린다.
- 띄운 것도 브라우저 기본 스크롤바라 끌기·휠·모양이 같다.

### 가로 스크롤바

세로와 따로 판별한다.

| 순서 | 영역의 구조 | 하는 일 |
| --- | --- | --- |
| 1 자기 여백 | 스크롤 영역 자신의 아래 여백이 스크롤바 높이 이상이다 | 그 여백을 줄인다 |
| 2 바깥 여백 | 바깥 아래에 여백이나 빈 자리가 있다 | 스크롤바를 영역 바로 아래에 띄운다 |
| 3 겹치기 | 둘 다 안 된다 | 스크롤바를 내용의 아래쪽 위에 띄운다(세로와 같이 배경은 투명하다) |

- 브라우저는 세로·가로 스크롤바를 한쪽만 숨길 수 없다.
- 그래서 한쪽이라도 띄우면 원래 스크롤바는 둘 다 숨기고 둘 다 띄운 것으로 그린다.
- 자리는 축마다 따로 정해진다 — 세로는 오른쪽 바깥, 가로는 내용 위가 될 수 있다.

## 그 밖에 하는 일

### 스크롤바 자리를 비워 둔 영역 (`scrollbar-gutter: stable`)

- 풀어도 내용이 밀리지 않을 때만 그 설정을 풀어 빈 띠를 없앤다.
- 풀어도 되는 때: 위 방식 중 하나로 받을 수 있거나, 내용이 영역보다 넓어 스크롤바가 생겨도 움직이지 않을 때.
- 그 밖에는 손대지 않는다.

### 스크롤바를 늘 띄워 두는 영역 (`overflow: scroll`)

- 보통 영역과 똑같이 다룬다.
- 넘치면 위 방식으로 받는다.
- 넘치지 않으면 원래 스크롤바의 빈 띠를 숨기고 아무것도 띄우지 않는다. 여백을 줄여 받는 구조든 띄워서 받는 구조든 같다(입력창은 뺀다 — 아래 「입력창」).
- 그래서 「내용이 짧아도 늘 보이던 빈 스크롤바」는 굴릴 것이 있을 때만 보이게 바뀐다.
- 내용 폭은 두 경우가 같다.
- 이런 영역은 내용이 늘고 줄 때마다 다시 판별한다.

### 페이지 전체 (브라우저 창) 스크롤

- 세로 스크롤바를 같은 순서로 본다.
- 바깥이 없으므로 3 은 건너뛴다.
- 겹치기는 화면 오른쪽 끝에 띄운다.
- 창 스크롤바가 그대로 남는 방식(1·2)이면, 화면 폭을 따라 놓이는 요소도 스크롤바가 없을 때의 자리에 맞춘다 — 화면에 고정한 헤더, 떠 있는 버튼, 가운데 띄운 알림, 페이지 구석에 붙여 둔 상자.
  - 화면 폭을 꽉 채운 것은 스크롤 영역과 같은 뜻으로 자기 오른쪽 여백을 줄인다(내용이 가운데 정렬이면 왼쪽 여백을 준다).
  - 그 밖의 것은 그 차이만큼 옮긴다(`translate`).
  - 차이는 창 스크롤바를 아주 잠깐 숨겨서 직접 잰다. 요소를 어떻게 붙여 놨는지 추측하지 않는다.
- 페이지 스크롤을 잠그는 코드(모달)가 사라진 스크롤바 자리를 여백으로 대신 채웠으면, 써 둔 값을 스크롤바가 돌아올 때까지 그대로 둔다. 같이 되돌리면 내용이 밀린다.

### 입력창 (`textarea`)

- 기본으로는 보지 않는다. `textarea` 옵션을 켰을 때만 같은 순서로 본다([설정](./configuration.md#옵션)).
- 입력창에는 shadow root 를 붙일 수 없어 3·4 는 적용되지 않는다. 1(자기 여백)과 `manual` 만 된다.
- 글이 늘어 스크롤바가 생기는 순간에 판별하고, 사라지면 되돌린다.
- 늘 띄워 두는 스크롤바(`overflow: scroll`)의 빈 띠는 입력창에서는 숨기지 않는다. 글이 바뀌어 넘치게 되는 것(값만 바뀐다)을 알아챌 수 없기 때문이다.
- 옵션을 켜지 않으면, 다른 스크롤 영역을 꽉 채운 자식으로 있는 입력창의 여백도 건드리지 않는다.

### 겹친 영역

- 스크롤 영역 안에 스크롤 영역이 있으면(페이지 전체 안의 영역 포함) 바깥 것부터 판별하고 적용한 뒤에 안쪽 것을 판별한다.
- 바깥 영역이 자기 스크롤바를 받으려고 줄인 여백을 안쪽 영역이 또 쓰지 않게 하려는 것이다.

## 다시 판별하는 때

모든 영역:

- 영역이나 그 내용의 크기가 바뀔 때
- 요소가 붙고 떨어지거나 class·style·글자가 바뀔 때
- 이미지가 다 불러와졌을 때
- 창 크기가 바뀔 때

바깥의 빈 자리에 띄운 영역은 그 자리 둘레 요소의 크기도 지켜본다:

- 옆 요소가 넓어져(테두리·안쪽 여백만 늘어도) 그 자리를 채우면 겹치기로 바꾼다.
- 옆 요소가 크기는 그대로인 채 자리를 옮겨 와(인라인 style 로 옮기거나 움직임 효과가 끝난 자리가) 그 자리를 채워도 겹치기로 바꾼다.
- 다시 비면 바깥으로 돌아온다.

움직임 효과 중이라 바깥에 못 붙었던 영역은 그 효과가 끝날 때 다시 해 본다.

## 화면에 남기는 것

스크롤 영역과 그 둘레 요소에 아래를 쓴다. 장치가 내려가면 shadow root 를 뺀 나머지를 전부 되돌린다.

| 무엇 | 어디에 | 왜 |
| --- | --- | --- |
| 인라인 style — `padding-right`·`padding-left`·`padding-bottom`·`margin-right`·`width`·`scrollbar-gutter` | 스크롤 영역, 그 안쪽 자식, (예비 방식에서) 바깥 틀 | 여백을 줄이고 더한다. `margin-right`·`width` 는 예비 방식(넓히기)에서만 쓴다 |
| CSS 변수 `--sbw`·`--sbh` | 스크롤 영역 | `manual` 설정에서 화면 코드가 받는다 |
| 속성 `data-scrollbar-undo` | 위 style 을 바꾼 요소 | 원래 값을 적어 둔다 |
| 속성 `data-scrollbar-overlay` | 스크롤바를 띄운 영역(페이지 전체면 `html`) | 원래 스크롤바를 숨긴다 |
| shadow root | 스크롤바를 띄운 영역 | 띄운 스크롤바를 자식 목록 밖에 둔다. 자식은 `<slot>` 으로 그대로 보인다. **장치가 내려가도 남는다**(안의 스크롤바만 숨긴다) |
| 속성 `data-scrollbar-method`·`data-scrollbar-method-x`·`data-scrollbar-why` | 스크롤 영역 | `debug` 를 켰을 때만. 고른 방식과 까닭을 적는다 |
| 요소 `[data-scrollbar-debug]` | `body` 끝 | `debug` 를 켰을 때만. 진단 표시를 그리는 층 — 화면 전체를 덮지만 누름은 통과시키고, 그림은 그 요소의 shadow root 안에 그린다 |
| 속성 `data-scrollbar-nudge` | 스크롤바를 띄운 영역 | 다시 판별할 때 한순간 붙였다 뗀다 — Safari 계열에서 숨겼던 스크롤바를 다시 그리게 하려는 것이다 |
| `<style>` 하나 | `head` | 원래 스크롤바를 숨기는 규칙 |
| `window` 의 오류 리스너 하나 | — | 「ResizeObserver loop」 알림을 가로챈다(`quiet` 가 참일 때만 가로챈다) |
| 요소 `[data-scrollbar-ghost-page]` | `body` 끝 | 페이지 전체에 띄운 스크롤바 |

알아 둘 것:

- 스크롤 영역의 **자식 목록은 건드리지 않는다.** React 등이 관리하는 DOM 과 부딪히지 않게 하려는 것이다.
- shadow root 가 붙은 요소에는 바깥 CSS 가 그대로 적용된다(자식은 light DOM 에 그대로 있다).
- 인라인 style 을 쓰므로, 같은 속성을 인라인으로 직접 바꾸는 코드가 있으면 그 값이 원래 값으로 취급된다.

## 브라우저 지원

| 기능 | 필요한 것 | 없으면 |
| --- | --- | --- |
| 자기 여백·가운데 정렬·세로 겹치기 | `ResizeObserver`, shadow DOM | — |
| 바깥에 띄우기 · 가로 스크롤바 띄우기 · 격자·가로 배치 영역의 겹치기 | CSS anchor positioning — Chrome·Edge 125, Safari 26, Firefox 147 부터 [1] | 세로는 예비 방식(영역을 `S` 만큼 넓히기)이나 겹치기로, 가로는 원래 스크롤바 그대로. 격자·가로 배치 영역은 손대지 않는다 |

anchor positioning 이 있어도 구조에 따라 스크롤바가 제자리에 붙지 않을 수 있다.

- 예: 스크롤 영역 자신에 `transform`·`filter` 가 걸린 경우.
- 띄운 직후 자리를 재서 안 붙었거나 조상에 잘려 안 보이면, 그 영역은 anchor positioning 이 없는 브라우저와 같은 방식으로 받는다.
- 움직임 효과가 끝나거나 창 크기가 바뀌면 다시 해 본다.

실제로 확인한 환경은 [검증 현황](./troubleshooting.md#검증-현황)에 있다.
