## 문제 해결

### 진단 표시로 보기

「무엇을 했는지 안 보인다」가 가장 큰 불안이다. `debug` 를 켜면 두 가지가 생긴다 — 화면에 그려지는 것과, 영역에 붙는 속성.

#### 화면에 그려지는 것

손을 댔거나 손대려다 못 한 스크롤 영역마다 아래가 겹쳐 그려진다. 색은 방식별이다.

| 그려지는 것 | 뜻 |
| --- | --- |
| 굵은 테두리와 옅은 칠 | 그 스크롤 영역 |
| 진한 띠 | 스크롤바가 놓인 자리 — 자기 여백·가운데 정렬·겹치기는 영역 안쪽 끝, 바깥에 띄우기는 영역 밖 |
| 빗금 띠 | 줄이거나 더한 뒤의 여백. 영역 자신이 아니라 안쪽 자식의 여백을 바꿨으면 그 자식 자리에 그려진다 |
| 점선 사각형 | 스크롤바가 없을 때의 내용 자리. 스크롤바가 생겨도 내용이 이 안에 그대로 있으면 밀리지 않은 것이다 |
| 왼쪽 위 딱지 | 세로(`↕`)·가로(`↔`)에 고른 방식, 스크롤바 굵기(`S`·`H`), 바깥에 띄울 때 떨어뜨린 거리(`gap`), 바꾼 값의 전 → 후, 까닭 |

딱지의 예:

| 딱지 | 읽는 법 |
| --- | --- |
| `↕ padding · S 11 · padding-right 24 → 13` | 세로 스크롤바(11px)를 자기 여백으로 받았다. 오른쪽 여백을 24 에서 13 으로 줄였다 |
| `↕ center · S 11 · padding-left 0 → 11` | 가운데 정렬로 받았다. 왼쪽에 11 을 더했다 |
| `↕ center · S 11 · child padding-right 16 → 5` | 폭을 꽉 채운 안쪽 자식의 오른쪽 여백을 줄였다 |
| `↕ outside · S 11 · gap 2` | 바깥에 띄웠다. 테두리 2px 을 건너 영역에서 2px 떨어진 자리다 |
| `↕ overlay · S 11 — outside-occupied` | 내용 위에 겹쳤다. 바깥 자리에 다른 요소가 있어서다 |
| `↕ outside · S 11 · ↔ overlay · H 11` | 세로는 바깥, 가로는 내용 위 |

알아 둘 것:

- 화면 맨 위에 따로 띄운 층에 그린다. 스크롤 영역 안에는 아무것도 끼워 넣지 않고, 클릭도 가로채지 않는다.
- 손댈 일이 없었던 영역(스크롤바가 없음·꺼 둠·제외함)은 그리지 않는다. 그런 영역도 아래 속성은 붙는다.
- 층이 맨 위에 있어서, 고정된 머리글 밑으로 굴러 들어간 영역의 테두리가 머리글 위에 보일 수 있다.
- 딱지는 글자 길이대로 그려져, 좁은 영역에서는 영역 밖으로 넘칠 수 있다.
- 영역 안에 영역이 있으면 띠와 점선이 겹쳐 보인다.
- 스크롤바가 생겨야 그릴 것이 생긴다. 내용이 넘치지 않는 영역은 표시가 없는 것이 정상이다.

#### 영역에 붙는 속성

개발자 도구에서 그 영역을 고르면 보인다. 테스트에서 읽어 쓸 수도 있다.

| 속성 | 뜻 |
| --- | --- |
| `data-scrollbar-method` | 세로 스크롤바에 고른 방식 |
| `data-scrollbar-method-x` | 가로 스크롤바에 고른 방식 |
| `data-scrollbar-why` | 그 방식이 된 까닭 — 더 앞선 방식을 못 쓴 이유(아래 「까닭」 표) |

방식:

| 방식 | 뜻 | 색 |
| --- | --- | --- |
| `padding` | 1 자기 여백을 줄였다 | 초록 |
| `center` | 2 가운데 정렬로 받았다 | 파랑 |
| `outside` | 3 바깥에 띄웠다 | 보라 |
| `overlay` | 4 내용 위에 겹쳤다 | 주황 |
| `widen` | 예비 방식으로 영역을 넓혔다 | 노랑 |
| `manual` | `manual` 설정이라 폭만 내려 줬다 | 검정 |
| `none` | 아무것도 하지 않았다 | 회색 점선(까닭이 「손댈 일 없음」이면 그리지 않는다) |

까닭 — 손댈 일이 없었다:

| 까닭 | 뜻 |
| --- | --- |
| `no-scrollbar` | 스크롤바가 떠 있지 않다(넘치지 않거나, 겹쳐 뜨는 스크롤바 환경이다) |
| `nothing-to-scroll` | 스크롤바는 늘 띄워 두는 설정인데 굴릴 것이 없다 — 아무것도 띄우지 않았다 |
| `off` · `excluded` | `data-scrollbar="off"` 가 붙어 있다 · `exclude` 선택자에 걸렸다 |

까닭 — 바깥에 못 띄웠다:

| 까닭 | 뜻 |
| --- | --- |
| `outside-too-narrow` | 바깥 여백·빈 자리가 스크롤바 폭보다 좁다 |
| `outside-occupied` | 스크롤바가 놓일 자리에 다른 요소가 있다(옆 패널, 여백 안의 버튼) |
| `outside-behind-box` | 바깥에 빈 자리는 있지만, 사이에 배경·테두리가 있는 상자나 넘친 부분을 자르는 틀이 있다 |
| `outside-gap-over-limit` | 건너야 하는 테두리 두께의 합이 `stayClose` 를 넘는다 |
| `outside-is-scroller` | 바깥 틀이 그 자체로 스크롤 영역이다 |
| `outside-none` | 문서 끝까지 올라가도 쓸 여백이 없다 |
| `outside-clipped-or-unanchored` | 바깥에 띄워 봤지만 조상에 잘려 안 보이거나 제자리에 붙지 않았다 |
| `no-anchor-positioning` | 브라우저에 anchor positioning 이 없다 |
| `page-has-no-outside` | 페이지 전체(브라우저 창) 스크롤이라 바깥이 없다 |

까닭 — 그 밖:

| 까닭 | 뜻 |
| --- | --- |
| `cannot-attach` | 스크롤바를 띄울 수 없는 요소다(`ul`·`table`·`textarea`, 웹 컴포넌트 태그, 이미 shadow root 가 있는 요소) |
| `cannot-overlay` | 겹치기도 못 하는 구조다(가로로 넘치는데 가로 스크롤바를 띄울 수 없는 경우 등) |
| `center-too-narrow` | 가운데 정렬인데 좌우 빈 자리가 스크롤바보다 좁아, 내용 위에 겹쳤다 |
| `center-not-applicable` | `center` 설정인데 가운데 정렬로 받을 수 없는 구조다 |
| `gutter-kept` · `gutter-released` | 비워 둔 스크롤바 자리를 풀면 밀려서 그대로 뒀다 · 자리만 풀었다(지금은 스크롤바가 없다) |

### 증상별

#### 콘솔·오류 수집 도구에 `ResizeObserver loop completed with undelivered notifications` 가 찍힌다

- **원인**: 스크롤바가 생긴 것을 알아챈 그 자리에서 여백을 고치기 때문에 브라우저가 남기는 알림이다. 동작에는 문제가 없다.
- **조치**: 기본은 이 장치가 그 알림을 가로채 뒤에 등록된 리스너에 닿지 않게 한다(`quiet`). 먼저 등록된 리스너(개발 서버의 오류 표시 등)에는 보일 수 있다.

#### 스크롤바가 얇고 손을 떼면 사라진다. 장치가 안 도는 것 같다

- **원인**: 겹쳐 뜨는 스크롤바 환경이다. 밀림이 없어 할 일이 없다.
- **조치**: 폭을 차지하는 스크롤바로 보려면 운영체제 설정에서 스크롤 막대를 「항상」 표시로 바꾼다.

#### 바깥에 여백이 있는데 스크롤바가 내용 위에 겹친다

- **원인** (넷 중 하나다):
  - 바깥 여백이 스크롤바 폭보다 좁다.
  - 영역 바로 옆에 다른 요소가 붙어 있다.
  - 그 여백 안, 스크롤바가 놓일 자리에 다른 요소(닫기 버튼 등)가 떠 있다.
  - 여백이 아니라 빈 자리 쪽인데 사이에 테두리·배경이 있는 상자가 끼어 있다.
- **조치**: `debug` 를 켜고 그 영역의 `data-scrollbar-why` 를 본다. 바깥 여백을 스크롤바 폭 이상으로 주거나, 스크롤 영역 자신에 여백을 준다.

#### 스크롤바가 없을 때 오른쪽이 왼쪽보다 넓다

- **원인**: 스크롤바용으로 넣어 둔 오른쪽 여백이 남아 있다.
- **조치**: 그 여백을 지운다([적용 시 권장사항](./configuration.md#적용-시-권장사항)).

#### 늘 띄워 둔 스크롤바가 내용이 짧으면 안 보인다

- **원인**: 의도한 동작이다. 굴릴 것이 없으면 스크롤바를 띄우지 않는다.
- **조치**: 늘 보여야 하면 그 영역에 `data-scrollbar="off"` 를 붙인다.

#### 입력창(`textarea`)에서 글자가 밀린다

- **원인**: 입력창은 기본으로는 보지 않는다. 옵션을 켰는데도 밀리면 둘 중 하나다(진단 표시의 까닭이 `cannot-attach`).
  - 입력창의 오른쪽 여백이 스크롤바 폭보다 좁다.
  - 폭을 `box-sizing: content-box`(브라우저 기본값)로 못박은 입력창이다. 여백을 줄여도 글자 폭이 늘지 않는다.
- **조치**: `textarea` 옵션을 켠다. 입력창의 좌우 여백을 스크롤바 폭 이상으로 주고 `box-sizing: border-box` 를 준다. 아니면 `data-scrollbar="manual"` 로 폭을 받아 직접 맞춘다([설정](./configuration.md#옵션)).

#### 특정 영역만 끄고 싶다

- **조치**: 그 영역에 `data-scrollbar="off"` 를 붙인다.

## 제약사항

### 환경

**겹쳐 뜨는 스크롤바 환경에서는 아무것도 하지 않는다.**

- 맥의 기본 설정이나 모바일처럼 스크롤바가 폭을 차지하지 않으면(잰 폭 0) 밀림이 원래 없다.

**자식을 위에서 아래로 쌓지 않는 영역(격자·가로 배치·거꾸로 쌓기)의 겹치기는 anchor positioning 이 있어야 한다.**

- 없는 브라우저에서는 그런 영역을 겹치기로 받지 못해 손대지 않는다.

### 손대지 않는 것

**숫자로 넣은 오른쪽 여백은 고치지 않는다.**

- [적용 시 권장사항](./configuration.md#적용-시-권장사항) 참고.

**보지 않는 영역이 있다.**

- shadow root 안, iframe 안의 스크롤 영역.
- 입력창(`textarea`)은 `textarea` 옵션을 켜야 본다. 켜도 스크롤바를 띄우지는 못한다(여백 줄이기와 `manual` 만 된다).
- `exclude` 에 걸린 구역.

**크기를 지킬 수 없는 상자에는 여백 줄이기를 쓰지 않는다.**

- 크기를 안쪽 내용 기준(`box-sizing: content-box`)으로 못박은 상자는 여백을 줄이면 글자 칸은 그대로인 채 상자만 줄어든다.
- 그런 상자에서는 1·2번을 건너뛰고 다음 순서(바깥에 띄우기·겹치기)로 간다. 폭·높이를 고쳐 써서 맞추지는 않는다.
- 스크롤바를 띄울 수 없는 요소(입력창 등)가 이런 상자면 받을 방법이 없어 그대로 둔다. `box-sizing: border-box` 를 주면 받는다.

**화면 폭을 따라 놓이는 요소는 늘 제자리에 둘 수 있는 것이 아니다.**

- 창 스크롤바를 그대로 두는 페이지 전체(브라우저 창) 스크롤에서의 이야기다.
- 그대로 두는 것: 이미 `translate` 를 쓰는 요소, 다른 고정 요소를 품은 요소, 옮기면 창 스크롤바 뒤로 들어가는데 그만큼의 오른쪽 여백이 없는 요소. 이들은 스크롤바 폭만큼 밀린다.
- 가운데나 오른쪽에 맞춘 `body` 배경 그림은 그대로 밀린다.
- 요소에 `translate` 나 여백의 움직임 효과(transition)가 걸려 있으면, 맞추는 순간이 짧게 미끄러지듯 보일 수 있다.

**페이지 전체(브라우저 창)의 가로 스크롤바는 다루지 않는다.**

### 스크롤바를 띄울 때

**shadow root 는 되돌릴 수 없다.**

- 스크롤바를 띄운 영역(바깥에 띄우기·겹치기)에는 shadow root 를 붙인다. 한 번 붙인 shadow root 는 떼어 낼 방법이 없다.
- 장치를 내린 뒤에도 그 요소의 `shadowRoot` 는 남는다(안의 스크롤바는 숨긴다).
- 그래서 **그 요소에 나중에 `attachShadow` 를 부르는 코드는 예외가 난다.**
- 가장 걸리기 쉬운 것이 정의가 늦게 불러와지는 웹 컴포넌트다. 그래서 웹 컴포넌트 태그(이름에 `-` 가 든 태그)에는 shadow root 를 붙이지 않는다 — 그런 스크롤 영역은 아래 「스크롤바를 띄울 수 없는 요소」와 같이 다룬다.
- 보통 태그인데 나중에 shadow root 를 붙이는 코드가 있으면, 그 요소에 `data-scrollbar="off"` 나 `manual` 을 붙여 스크롤바를 띄우지 않게 한다.
- 여백 줄이기·가운데 정렬로 받는 영역에는 shadow root 를 붙이지 않는다.

**스크롤바를 띄울 수 없는 요소가 있다.**

- 띄운 스크롤바는 스크롤 요소의 shadow root 에 둔다.
- 해당하는 요소: shadow root 를 붙일 수 없는 태그(`ul`·`table`·`textarea` 등), 이미 shadow root 가 있는 요소, 웹 컴포넌트 태그.
- 이런 요소에는 1·2번만 적용된다.
- 바깥에 자리가 있고 그 영역이 눈에 보이는 상자(테두리·배경)가 아니면 예비 방식으로 영역을 `S` 만큼 넓힌다.
- 그것도 안 되면 손대지 않는다(스크롤바가 생길 때 밀린다).
- 그런 영역은 `manual` 로 직접 받을 수 있다.

**띄운 스크롤바가 놓인 자리의 클릭은 스크롤바가 받는다.**

- 눈에는 손잡이만 보이지만, 스크롤바 폭만큼의 띠 전체가 누름을 받는다.
- 겹치기에서는 내용의 오른쪽 끝(가로는 아래 끝) 그 폭만큼이 해당한다.

**띄운 스크롤바를 잘라 내는 카드 안의 영역, 자신이 오려 내는 영역은 바깥에 띄우지 못한다.**

- 해당하는 카드: 넘친 부분을 자르면서 `transform`·`filter`·`backdrop-filter` 같은 것이 걸린 카드, 모양대로 오려 내거나(`clip-path`) 가림막(`mask`)을 씌운 카드.
- 바깥에 자리가 있어도 내용 위에 겹친다.
- 실제로는 안 잘리는데 잘린다고 보는 경우도 있다(페이지 전체를 스크롤 못 하게 잠가 둔 화면 등). 그때도 겹치기로 간다.

**스크롤바를 늘 띄워 두는 설정은 「굴릴 것이 있을 때만 보이는」 것으로 바뀐다.**

- `overflow: scroll` 로 늘 보이게 해 둔 빈 스크롤바는 내용이 넘치지 않으면 보이지 않는다([동작 방식](./how-it-works.md#그-밖에-하는-일)).

**세로·가로를 둘 다 내용 위에 띄우면 손잡이가 겹칠 수 있다.**

- 오른쪽 아래 모서리에서 두 손잡이가 겹칠 수 있다.

**더 큰 스크롤 영역 안에서 반쯤 가려진 영역은 스크롤바가 밖으로 보일 수 있다.**

- 바깥에 띄운 스크롤바가 그 큰 영역 밖으로 보일 수 있다(다 가려지면 숨는다).

### 다시 판별

**요소 변화 없이 모양만 바뀌는 경우는 바로 못 잡는다.**

- 해당하는 경우: 마우스를 올렸을 때만 넓어지는 요소, 움직임 효과, 늦게 적용된 글꼴.
- 다음에 그 영역을 굴리거나 창 크기를 바꿀 때 바로잡힌다.

**바깥의 빈 자리에 띄운 영역은 그 자리 둘레의 요소를 전부 지켜본다.**

- 지켜보는 것: 빈 자리를 판정한 틀과 그 바로 아래 자식들.
- 자식이 아주 많은 틀이면 지켜보는 수도 그만큼 는다.

### 이름과 표시

**`--sbw`·`--sbh` 는 이 장치가 쓰는 이름이다.**

- 스크롤 영역마다 인라인으로 적고(`manual` 이 아니면 `0px`), 걷을 때 지운다.
- 앱이 같은 이름의 변수를 인라인으로 직접 쓰면 덮이거나 지워진다.

**진단 표시의 그림은 확대·축소가 걸린 조상 아래에서 어긋날 수 있다.**

- 확대·축소(`transform: scale`)가 걸린 조상 아래에서 띠의 굵기와 자리가 어긋날 수 있다.
- 표시만 틀리고 판별은 그대로다.

### 판별의 한계

**모든 구조에서 같은 결과를 보장하지 않는다.**

- 판별은 화면에 그려진 크기·여백을 재서 하는 추정이다.
- 드문 구조에서는 방식을 잘못 고를 수 있다.
- 그런 영역은 [영역별 설정](./configuration.md#영역별-설정)으로 바로잡는다.

### 확인한 환경

| 엔진 | 확인한 스크롤바 | 비고 |
| --- | --- | --- |
| Chromium | 기본 15px, 얇게(thin) 11px, 꾸민 스크롤바(`::-webkit-scrollbar`) 11px·17px | — |
| Firefox | 기본 15px, 얇게 11px | 창을 띄워 돌렸다 — 창 없이 띄우면 스크롤바 폭이 0 이다 |
| WebKit(Safari 엔진) | 꾸민 스크롤바 11px·17px | 기본 스크롤바는 겹쳐 뜨는 방식(폭 0)이라 「아무것도 하지 않는다」만 확인했다 |

### 확인하지 못한 것

- 실제 윈도우(17px 는 꾸민 스크롤바로 흉내 냈다)
- Safari 에서 기본 스크롤바가 폭을 차지하는 설정
- Safari 26 그 자체(Playwright 의 WebKit 은 같은 엔진의 다른 빌드다) — 자동 테스트로는 못 돌린다. Safari 26.3 에서 데모 화면의 바깥에 띄우기 장면만 사람이 직접 봤다. 이때 테스트용 WebKit 에서는 안 나오던 문제(방금 띄운 스크롤바의 자리가 다음 화면 갱신에서야 잡힘) 하나를 찾아 고쳤다
- anchor positioning 이 없는 예전 브라우저

### 테스트가 단언하는 것

밀림과 방식:

- 스크롤바가 생기기 전후 내용 위치(밀림 0)
- 경우마다 고른 방식
- 스크롤바 폭 0 에서 아무것도 하지 않는지
- 크기를 안쪽 내용 기준으로 못박은 상자의 폭·높이가 그대로이고, 폭·높이를 고쳐 쓰지 않는지
- 높이가 내용으로 정해지는 상자와 폭을 비율로 준 상자의 크기를 숫자로 굳히지 않는지(줄이 늘거나 감싼 틀이 줄면 따라가는지)
- 폭을 꽉 채운 `content-box` 자식의 글자 폭이 그대로인지
- 예비 방식(넓히기)이 `content-box` 목록을 스크롤바 폭만큼만 넓히는지

띄운 스크롤바:

- 띄운 스크롤바가 제자리에서 잡히고 화면에 실제로 그려지는지
- 내용과 손잡이의 스크롤 맞물림
- 굴릴 것이 없을 때 누름을 가로채는 막대가 없는지
- 띄운 막대 위의 휠이 스크롤 영역으로 넘어가고 Ctrl+휠은 넘기지 않는지
- 웹 컴포넌트 태그에 shadow root 를 붙이지 않는지
- 띄운 스크롤바가 꾸민 손잡이의 테두리·칠 범위까지 따라가는지(투명 테두리로 가늘게 만든 손잡이)

다시 판별과 되돌리기:

- 옆 요소가 넓어지고 좁아질 때 다시 판별하는지
- 겹친 두 영역이 같은 순간에 다시 판별돼도 서로의 스크롤바가 겹치지 않는지
- 스크롤바가 사라진 뒤와 장치를 끈 뒤에 흔적이 없는지

옵션:

- `stayClose` — 한도 기본값과 다른 값
- `exclude` — 제외한 구역은 그대로이고 그 밖은 처리되는지
- `debug` — 진단 표시가 실제로 고른 방식과 같고 끄면 지워지는지, 진단을 켜도 고른 방식이 같은지
- `quiet` — 브라우저 알림을 가로채는 기본값과 끈 경우
- `textarea` — 기본값이면 입력창을 그대로 두는지(다른 영역을 꽉 채운 자식일 때도), 켜면 여백을 줄이고 글자 폭이 그대로인지, 여백이 좁은 입력창은 그대로 두는지, 늘 띄우는 스크롤바의 입력창에 글을 넣어도 스크롤바가 숨지 않는지, 걷으면 되돌아오는지

진단 층:

- 딱지에 스크롤바 굵기와 바꾼 값이 적히는지
- 스크롤바 자리 띠의 굵기가 원래 스크롤바와 같은지
- 내용 자리 점선이 실제 내용이 놓인 자리와 같은지
- 누름을 가로채지 않는지

설치:

- React 없이 본체만 불러 설치하고 걷을 수 있는지
- 본체가 React 를 불러오지 않는지
- 쓸 수 없는 환경에서 설치해도 예외가 없고 그 뒤의 설치·걷기가 정상인지
- 페이지 전체(브라우저 창) 스크롤에서 스크롤바가 생기고 사라질 때와 모달이 세 가지 방식으로 스크롤을 잠갔다 풀 때, 고정 헤더·본문·떠 있는 요소가 제자리에 있는지(배치 세 가지)
