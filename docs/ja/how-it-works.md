## 動作の概要

| やること | 内容 |
| --- | --- |
| 自動検出 | 画面の縦・横のスクロール領域を、計算済みスタイルで見つける。class 名や CSS の書き方には頼らない。後から追加される要素（モーダル・ドロップダウン）も見つける |
| 領域ごとの判定 | 一つの補正をすべての領域に同じように当てはめない。領域の構造を見て、四つの方式のうち一つを選ぶ（[自動判定の優先順位](#自動判定の優先順位)） |
| 縦・横を別々に | 二つのスクロールバーの場所を、それぞれ決める |
| 標準スクロールバーの維持 | 自前で描いたスクロールバーではなく、ブラウザ標準のスクロールバーを使う。`scrollbar-width`・`scrollbar-color`・`::-webkit-scrollbar` で装飾した見た目にも従う |
| スクロールバーの幅を測って使う | 幅を仮定せず、そのブラウザで測った値を使う |
| 再判定 | 領域や内容のサイズが変わったり、要素やスタイルが変わったりすると、再判定する |
| 元に戻す | 変更したパディング・変数・属性を要素ごとに記録しておき、このライブラリが取り外されると元に戻す。スクロールバーを浮かせた領域に付けた shadow root だけは取り外せず、残る（[制約事項](./troubleshooting.md#制約事項)） |
| 入れ子の領域 | スクロール領域の中にスクロール領域があるときは、外側から判定し、同じパディングを二つの領域が使わないようにする |
| 設定 | 全体にかけるオプション五つ（`stayClose`・`exclude`・`debug`・`quiet`・`textarea`）と、領域ごとに付ける `data-scrollbar`（無効化・方式の固定・手動調整）がある。何も渡さなくても動く |
| デバッグ表示 | オンにすると、画面上に領域ごとに何をしたかを描いて見せる: 選んだ方式と理由、スクロールバーが置かれた場所、減らしたり足したりしたパディングの前後の値、スクロールバーがないときの内容の位置 |

## 自動判定の優先順位

このライブラリの核心である。

- スクロールバーを一つの方法で補正することはしない。
- スクロールバーが表示された領域ごとに構造を分析して、**合う最初の方式**を使う。
- 以下で `S` は、そのブラウザで測ったスクロールバーの幅である。

### 縦スクロールバー

| 順序 | 領域の構造 | すること | 内容を隠すか |
| --- | --- | --- | --- |
| 1 自身のパディング | スクロール領域自身の右のパディングが `S` 以上ある | そのパディングを `S` の分だけ減らす。スクロールバーはその場所に表示される | いいえ |
| 2 中央寄せ | 内側の内容の左右の空きが同じ（差が 2px 以下） | 左に `S` を足す | いいえ |
| 3 外側の余白 | スクロール領域の右端が、外側の枠の余白（`S` 以上）に接しているか、右の外側が空いている | スクロール領域はそのままにして、スクロールバーだけを領域のすぐ外に浮かせる | いいえ |
| 4 重ねる | 上の三つがすべて使えない | スクロールバーを内容の右端の上に浮かせる | つまみが置かれた部分だけ、半透明で |

### 方式ごとの詳細

#### 1 自身のパディング

- **なぜあるか**: 最も一般的な構造である。領域の中で完結するので、外側への影響がない。

#### 2 中央寄せ

- **なぜあるか**: 中央に置かれた内容は、右だけを減らすと中央がずれる。両側を同じにしてはじめて、元の位置に留まる。

#### 1 と 2 はボックスの外側のサイズを変えない

- サイズを内側の内容基準（`box-sizing: content-box`）で固定したボックス（`width: 240px` のようなもの）は、パディングだけを減らすと、文字の領域はそのままでボックス全体が縮む。
- そのようなボックスにはこの方式を使わず、次の順序に移る。横スクロールバーの下のパディング（高さ）も同じである。
- 幅・高さを書き換えて合わせることはしない。割合で指定したサイズが数値で固定されてしまい、内容で決まるサイズを固定することになるからである。
- 幅いっぱいの内側の子要素のパディングを減らす場合も同じ基準である — 減らしても、その子要素の文字の領域がスクロールバーのないときと同じにならなければ使わない。
- 判断のしかた: スクロールバーがないときのサイズと、パディングを変えた後のサイズを測って、同じかどうかを見る。測るのは `content-box` のボックスだけである。

#### 3 外側の余白

- **なぜあるか**: 余白がスクロール領域ではなく外側の枠にある構造（枠いっぱいのリスト）である。領域に減らせるパディングがない。
- **枠線があるボックスでも同じ**: 外側に場所があれば、枠線のすぐ外に浮かせる。
- **囲む枠は何重でも通り抜ける**: 領域を余白なしで囲む枠（間に他の要素がなく、枠線だけがある）がそうである。
- **離れすぎたら使わない**: 越えた枠線の太さの合計が `stayClose`（デフォルト 12px）を超えたら 4 に行く。スクロールバーが自分の領域から離れて見えるからである。

3 を使わず 4 に行く場合:

| 場合 | 理由 |
| --- | --- |
| スクロール領域自身が形に切り抜いている（`clip-path`）か、マスク（`mask` — 上下の端をぼかす効果など）をかけている | 領域の外に浮かせたスクロールバーが、領域自身に切り取られて見えない |
| スクロールバーが置かれる場所に、別の要素（余白の中に浮かせてある閉じるボタンなど）がかかっている | 浮かせたスクロールバーがその要素を覆って、クリックを横取りしないようにするためである |

- 領域全体を覆う背景・装飾のレイヤーは、「その場所に置かれた要素」とは見なさない。

#### 4 重ねる

- **なぜあるか**: 行が端まで詰まったリストやグリッドのように、どこにも場所がない構造である。ずれる代わりに、内容の上に浮かせる方を選ぶ。
- **ここに来る配置**: 子要素を上から下へ積まない配置（グリッド・横並び・逆向きの積み）もここに来る。
- **最後である理由**: 内容を隠す方式は 4 だけだからである。

4 でも、スクロールバーの幅全体は隠さない。

- 浮かせたスクロールバーは、背景（つまみが行き来する帯）が透明である。
- つまみの色を別に指定していなければ、つまみも半透明（黒 35%）である。
- そのため、隠れるのはつまみが置かれた部分だけで、その部分も後ろの内容が透けて見える。
- 画面側のコードでつまみの色を指定してあれば（`scrollbar-color`・`::-webkit-scrollbar-thumb`）、その色をそのまま使う。
- ただし、浮かせたスクロールバーが置かれた場所へのクリックは、スクロールバーが受ける。

#### 3 と 4 はスクロールバーを別に浮かせる

- 元のスクロールバーを隠し、同じ見た目のスクロールバーを別に浮かせて、二つのスクロール位置を連動させる。
- 浮かせたものもブラウザ標準のスクロールバーなので、ドラッグ・ホイール・見た目は同じである。

### 横スクロールバー

縦とは別に判定する。

| 順序 | 領域の構造 | すること |
| --- | --- | --- |
| 1 自身のパディング | スクロール領域自身の下のパディングが、スクロールバーの高さ以上ある | そのパディングを減らす |
| 2 外側の余白 | 外側の下に余白や空きがある | スクロールバーを領域のすぐ下に浮かせる |
| 3 重ねる | どちらも使えない | スクロールバーを内容の下側の上に浮かせる（縦と同じく背景は透明である） |

- ブラウザは、縦・横のスクロールバーの片方だけを隠すことができない。
- そのため、片方でも浮かせると、元のスクロールバーは両方隠し、両方を浮かせたものとして描く。
- 場所は軸ごとに別々に決まる — 縦は右の外側、横は内容の上になることがある。

## そのほかにすること

### スクロールバーの場所を空けておく領域（`scrollbar-gutter: stable`）

- 解除しても内容がずれないときだけ、その設定を解除して空の帯をなくす。
- 解除してよいとき: 上の方式のいずれかで受けられるとき、または、内容が領域より広く、スクロールバーが現れても動かないとき。
- それ以外には手を触れない。

### スクロールバーを常に表示しておく領域（`overflow: scroll`）

- 通常の領域と同じに扱う。
- あふれたら、上の方式で受ける。
- あふれなければ、元のスクロールバーの空の帯を隠し、何も浮かせない。パディングを減らして受ける構造でも、浮かせて受ける構造でも同じである（テキストエリアは除く — 下の「テキストエリア」）。
- そのため、「内容が短くても常に見えていた空のスクロールバー」は、スクロールするものがあるときだけ見えるように変わる。
- 内容の幅は、どちらの場合も同じである。
- このような領域は、内容が増減するたびに再判定する。

### ページ全体（ブラウザウィンドウ）のスクロール

- 縦スクロールバーを同じ順序で見る。
- 外側がないので、3 は飛ばす。
- 重ねるは、画面の右端に浮かせる。

### テキストエリア（`textarea`）

- デフォルトでは対象にしない。`textarea` オプションをオンにしたときだけ、同じ順序で見る（[設定](./configuration.md#オプション)）。
- テキストエリアには shadow root を付けられないので、3・4 は適用されない。1（自身のパディング）と `manual` だけができる。
- 文章が増えてスクロールバーが現れた瞬間に判定し、消えたら元に戻す。
- 常に表示するスクロールバー（`overflow: scroll`）の空の帯は、テキストエリアでは隠さない。文章が変わってあふれるようになること（値だけが変わる）を検知できないからである。
- オプションをオンにしていなければ、他のスクロール領域を幅いっぱいに埋める子要素であるテキストエリアのパディングにも、手を触れない。

### 入れ子の領域

- スクロール領域の中にスクロール領域があるとき（ページ全体の中の領域を含む）は、外側から判定して適用した後に、内側を判定する。
- 外側の領域が自分のスクロールバーを受けるために減らしたパディングを、内側の領域がもう一度使わないようにするためである。

## 再判定するタイミング

すべての領域:

- 領域やその内容のサイズが変わったとき
- 要素が追加・削除されたり、class・style・文字が変わったりしたとき
- 画像の読み込みが終わったとき
- ウィンドウサイズが変わったとき

外側の空きに浮かせた領域は、その場所の周りの要素のサイズも監視する:

- 隣の要素が広がって（枠線や内側のパディングが増えただけでも）その場所を埋めたら、重ねるに切り替える。
- 隣の要素がサイズはそのままで場所を移してきて（インライン style で移したり、アニメーションが終わった位置が）その場所を埋めても、重ねるに切り替える。
- 再び空いたら、外側に戻る。

アニメーション中で外側に付けられなかった領域は、そのアニメーションが終わるときにもう一度試す。

## 画面に残すもの

スクロール領域とその周りの要素に、次を書き込む。このライブラリが取り外されると、shadow root を除いてすべて元に戻す。

| 何を | どこに | なぜ |
| --- | --- | --- |
| インライン style — `padding-right`・`padding-left`・`padding-bottom`・`margin-right`・`width`・`scrollbar-gutter` | スクロール領域、その内側の子要素、（予備の方式で）外側の枠 | パディングを減らしたり足したりする。`margin-right`・`width` は予備の方式（広げる）でのみ使う |
| CSS 変数 `--sbw`・`--sbh` | スクロール領域 | `manual` 設定で、画面側のコードが受け取る |
| 属性 `data-scrollbar-undo` | 上の style を変えた要素 | 元の値を書き留めておく |
| 属性 `data-scrollbar-overlay` | スクロールバーを浮かせた領域（ページ全体なら `html`） | 元のスクロールバーを隠す |
| shadow root | スクロールバーを浮かせた領域 | 浮かせたスクロールバーを、子要素のリストの外に置く。子要素は `<slot>` でそのまま見える。**このライブラリが取り外されても残る**（中のスクロールバーだけを隠す） |
| 属性 `data-scrollbar-method`・`data-scrollbar-method-x`・`data-scrollbar-why` | スクロール領域 | `debug` をオンにしたときだけ。選んだ方式と理由を書く |
| 要素 `[data-scrollbar-debug]` | `body` の末尾 | `debug` をオンにしたときだけ。デバッグ表示を描くレイヤー — 画面全体を覆うがクリックは通し、描画はその要素の shadow root の中に行う |
| 属性 `data-scrollbar-nudge` | スクロールバーを浮かせた領域 | 再判定のときに一瞬付けて外す — Safari 系で隠していたスクロールバーを描き直させるためである |
| `<style>` 一つ | `head` | 元のスクロールバーを隠すルール |
| `window` のエラーリスナー一つ | — | 「ResizeObserver loop」通知を横取りする（`quiet` が `true` のときだけ横取りする） |
| 要素 `[data-scrollbar-ghost-page]` | `body` の末尾 | ページ全体に浮かせたスクロールバー |

知っておくこと:

- スクロール領域の**子要素のリストには手を触れない。** React などが管理する DOM と衝突しないようにするためである。
- shadow root が付いた要素にも、外側の CSS はそのまま適用される（子要素は light DOM にそのまま残る）。
- インライン style を使うので、同じプロパティをインラインで直接書き換えるコードがあると、その値が元の値として扱われる。

## ブラウザ対応

| 機能 | 必要なもの | ないとき |
| --- | --- | --- |
| 自身のパディング・中央寄せ・縦方向の重ね | `ResizeObserver`、shadow DOM | — |
| 外側に浮かせる · 横スクロールバーを浮かせる · グリッド・横並び領域での重ね | CSS anchor positioning — Chrome・Edge 125、Safari 26、Firefox 147 から [1] | 縦は予備の方式（領域を `S` の分だけ広げる）か重ねるに、横は元のスクロールバーのまま。グリッド・横並びの領域には手を触れない |

anchor positioning があっても、構造によってはスクロールバーが所定の位置に付かないことがある。

- 例: スクロール領域自身に `transform`・`filter` がかかっている場合。
- 浮かせた直後に位置を測って、付いていないか、祖先に切り取られて見えなければ、その領域は anchor positioning がないブラウザと同じ方式で受ける。
- アニメーションが終わったり、ウィンドウサイズが変わったりすると、もう一度試す。

実際に確認した環境は[検証状況](./troubleshooting.md#検証状況)にある。
