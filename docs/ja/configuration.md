## 適用範囲 — コンポーネントを置く場所が範囲である

動いている間は、その画面全体（ドキュメント全体）のスクロール領域を扱う。そのため、どこに置くか（React なしで使うときは、いつ組み込んでいつ取り外すか）で範囲を決める。

| 範囲 | 置く場所 |
| --- | --- |
| アプリ全体 | アプリの最上位のレイアウト |
| 特定のページ（パス）だけ | そのページやページ群のレイアウト。そのページにいる間だけ動き、離れると元に戻す |

- **段階的な導入**: 1ページからオンにして、広げていくのは、これで行う。
- **共通領域にも適用される**: オンになっている間は、そのページの本文だけでなく、一緒に表示される共通領域（サイドバー・ヘッダー・モーダル）にも適用される。オンにしたページとオンにしていないページを行き来すると、共通領域のスクロールバーの見え方が違って見えることがある。
- **一部だけオンにすることはできない**: 画面の一部（コンテナ一つ）だけをオンにするオプションはまだない。一部を**除く**のは `exclude` で行う。

## オプション

すべて画面全体にかける設定である。領域ごとに変えるには[領域ごとの設定](#領域ごとの設定)を使う。

| オプション | 値 | デフォルト | 意味 |
| --- | --- | --- | --- |
| `stayClose` | 数値（px） | `12` | スクロールバーを外側に浮かせるとき、領域の端から離してよい距離の上限 |
| `exclude` | CSS セレクタの文字列 | なし | このセレクタに該当する要素とその配下には手を触れない |
| `debug` | 真偽値 | `false` | デバッグ表示をオンにする — 領域ごとに何をしたかを画面に描く |
| `quiet` | 真偽値 | `true` | ブラウザが出す「ResizeObserver loop」通知を横取りする |
| `textarea` | 真偽値 | `false` | テキストエリア（`textarea`）も対象にする |

```tsx
<MrScroll stayClose={4} exclude=".some-widget, .third-party" textarea debug />
```

```ts
installMrScroll({ stayClose: 4, exclude: ".some-widget, .third-party", textarea: true, debug: true });
```

### `stayClose` — 外側に浮かせるときに離れてよい距離

- **何を測るか**: 領域を余白なしで囲むカードや枠の枠線を越えて外側の余白に浮かせると、越えた枠線の太さの合計の分だけ、スクロールバーが領域から離れる。
- **超えたら**: その距離がこの値を超えると、外側には浮かせず、内容の上に重ねる。
- **デフォルト値（12px）**: よくある枠線（1px から 4px）には引っかからない。
- **制限をなくすには**: `Infinity` を渡す。
- **適用される軸**: 縦・横の両方に適用される。
- **不正な値**: 負の数や数値でない値は、デフォルト値として扱う。
- **誤差**: 接しているかどうかを 1px の誤差で見るので、上限の近くでは 1px や 2px ずれることがある。

### `exclude` — 手を触れない区域

- **範囲**: セレクタに該当する要素と、**その配下すべて**のスクロール領域を、見つけもせず、手も触れない。
- **外側の領域にも手を触れない**: 外側のスクロール領域が自分のスクロールバーを受けるために、その区域のパディングを減らすこともない。
- **いつ使うか**: マークアップに `data-scrollbar="off"` を付けられない外部ウィジェットを除くのに使う。
- **複数**: カンマで複数を渡せる。
- **誤ったセレクタ**: ないものとして扱う。

### `debug` — デバッグ表示

手を加えたスクロール領域ごとに、画面上に重ねて描く。

- 方式ごとの色の枠線
- スクロールバーが置かれた場所
- 減らしたり足したりしたパディング
- スクロールバーがないときの内容の位置
- 方式・スクロールバーの太さ・変更した値・理由を書いたラベル

知っておくこと:

- 同じ内容を、領域の属性にも書く。
- スクロール領域には何も差し込まず、クリックを横取りせず、判定結果も変えない。
- オンにしている間は領域の位置を毎フレーム測り直すので、開発中だけオンにする。
- 見方は[トラブルシューティング](./troubleshooting.md#トラブルシューティング)にある。

### `quiet` — ブラウザ通知の横取り

- **なぜあるか**: スクロールバーが現れたのを検知したその場でパディングを直すので、ブラウザが `ResizeObserver loop completed with undelivered notifications` という通知を頻繁に出す。動作には問題がないが、エラー収集ツールに溜まる。
- **デフォルト（`true`）**: この通知を横取りして、このライブラリより後に登録されたリスナーに届かないようにする。
- **注意**: **ほかのコードが出した同じ通知も、一緒に隠れる。**
- **オフにするには**: その通知を自分で見たいときは `false` を渡す。

### `textarea` — テキストエリアも対象にする

- **デフォルト（`false`）**: テキストエリアは対象にしない。高さを内容に合わせるコードと干渉しやすいからである。
- **オンにすると**: 他のスクロール領域と同じ順序で判定する。
- **できることは二つ**: テキストエリアにはスクロールバーを浮かせられない（shadow root を付けられないタグである）。

| テキストエリアの状態 | 結果 |
| --- | --- |
| 右のパディングがスクロールバーの幅以上ある | そのパディングを減らす。文字が置かれる幅がそのままなので、改行位置は変わらない |
| 右のパディングがスクロールバーより狭い | そのままにする。文字がスクロールバーの幅の分だけずれる |
| 幅を `box-sizing: content-box` で固定している（ブラウザのデフォルト） | そのままにする。パディングを減らしても文字幅は増えず、ボックスが縮むだけだからである |
| `data-scrollbar="manual"` を付けた | 幅（`--sbw`）を受け取って、自分で合わせる |

- **受け止められるようにするには**: テキストエリアの左右のパディングをスクロールバーの幅以上にし、幅を数値で指定したテキストエリアには `box-sizing: border-box` を指定する（ほとんどの CSS リセットは、すでにそうしている）。
- **テキストエリアのサイズは変わらない**: 幅・高さを書き換えない。
- **子要素であるテキストエリアも同じ**: オプションをオンにしていなければ、他のスクロール領域を幅いっぱいに埋める子要素であるテキストエリアのパディングにも、手を触れない。
- **常に表示するスクロールバーはそのままにする**: `overflow: scroll` のテキストエリアの空のスクロールバーは隠さない。文章が変わってあふれるようになることを検知できないからである。
- **元に戻す**: オプションをオフにするか取り外すと、元の値に戻す。

### 複数回組み込んだとき

- 最後に組み込んだもののオプションを使う。
- それを取り外すと、その前のものに戻る。
- オプションが変わると、見ていた領域をすべて再判定する。

## 領域ごとの設定

自動判定が合わない領域には、スクロール要素に `data-scrollbar` を付ける。領域ごとに渡す設定はこれ一つである。付けないのがデフォルトである。

| 値 | 動作 | いつ使うか |
| --- | --- | --- |
| `off` | その領域を、判定と修正の対象から外す。縦・横ともに元のスクロールバーのままである | このライブラリが触れてはいけない領域 — スクロールバーを自前で扱うコンポーネント。マークアップに手を入れられない外部ウィジェットは、オプション `exclude` で除く |
| `center` | 左右の空きが違っていても、**中央寄せの方式（2番）として判定させる** | 中央寄せなのに、左右の空きが 2px を超えて違うために、自動判定が 2番を選べなかった領域 |
| `manual` | **自分で調整する。** 縦スクロールバーの幅を CSS 変数 `--sbw` で、横スクロールバーの高さを `--sbh` で渡すだけで、自動判定は行わない。その値をどこにどう使うかは、画面側のコードが決める | 自動判定の代わりにパディングを自分で決めたい領域 — 行ごとにパディングがあるリスト、スクロールバーと内容の間隔を別に決めたい領域、スクロールバーを浮かせられないリストタグ・表・テキストエリア（テキストエリアは `textarea` オプションをオンにしないと値が来ない） |

```html
<!-- 手を触れない -->
<div data-scrollbar="off" style="overflow-y: auto">…</div>

<!-- 2番の方式に固定する -->
<div data-scrollbar="center" style="overflow-y: auto">
  <article style="max-width: 720px; margin-left: 40px">…</article>
</div>
```

### `center` — 内容を中央へ移す設定ではない

- 判定を 2番の方式に固定する設定である。
- 左にスクロールバーの幅の分だけパディングを足して、すでに中央に置かれた内容が、スクロールバーが現れても元の位置に留まるようにする。
- 2番を適用できない構造（内側に空きがない場合など）では、3番・4番には移らず、何もしない。
- スクロール領域自身の右のパディングが十分にあれば、1番が先に適用される。

### `manual` — スクロールバーの幅を受け取って自分で調整する

自動判定は「このライブラリが自分で選ぶ」であり、`manual` は「幅だけ知らせるので、自分で決める」である。

- この設定を付けた領域では、元のスクロールバーがそのまま表示される。このライブラリは、中央寄せ・外側に浮かせる・重ねるのいずれも行わない。
- このライブラリがすることは、その領域に値を二つ書き込むことだけである。
  - `--sbw` は縦スクロールバーの幅、`--sbh` は横スクロールバーの高さである。
  - スクロールバーが表示されていればその太さ（例: `11px`）、なければ `0px` である。
- 領域の中のどの要素でも、`var(--sbw, 0px)`・`var(--sbh, 0px)` でその値を受け取れる。行、ヘッダー行、下部のボタン行など、どこでもよい。

| 望むこと | 使う式 | 結果 |
| --- | --- | --- |
| 内容がずれないようにする | `padding-right: calc(16px - var(--sbw, 0px))` | パディングがスクロールバーの幅の分だけ減り、スクロールバーが現れても内容の位置が同じになる |
| スクロールバーと内容の間を最低 8px は空ける | `padding-right: max(8px, calc(16px - var(--sbw, 0px)))` | スクロールバーが太くても 8px は離れる。足りない分は内容がずれる |
| スクロールバーがあるときに、パディングをより多く取る | `padding-right: calc(24px - var(--sbw, 0px))` | スクロールバーがなければ 24px、あれば内容とスクロールバーの間が `24px − スクロールバーの幅` になる |
| スクロール領域の外の行を、スクロールバーの幅に合わせる | 値を受け取る要素が領域の中になければならない | 領域の外の要素には値が来ない |

```html
<ul data-scrollbar="manual" style="overflow-y: auto">
  <li style="padding-right: calc(16px - var(--sbw, 0px))">…</li>
</ul>
```

知っておくこと:

| 状況 | 内容 |
| --- | --- |
| ずれないようにするには | 「右のパディング + スクロールバーの幅」が、スクロールバーの有無にかかわらず同じでなければならない。表の最初の行がその式である。違う書き方をすると、その差の分だけずれ、それは使う側の選択である |
| パディングがスクロールバーより小さいとき | 負の値になって、その宣言は無視される。`max(0px, …)` で包む |
| 1番（自身のパディング）が先である | スクロール領域自身の右のパディングがスクロールバーの幅以上あれば、このライブラリがそのパディングを減らし、`--sbw` は 0 になる |
| 横も同じである | スクロール領域自身の下のパディングがスクロールバーの高さ以上あれば、このライブラリがそのパディングを減らし、`--sbh` は 0 になる。そうでなければ `--sbh` で高さを渡し、横スクロールバーも浮かせない |
| 横のあふれが縦スクロールバーのためだけに生じている場合 | `--sbh` は 0 である。縦を受ければ、そのあふれも一緒になくなるからである |
| 内側にさらにスクロール領域があるとき | その中では 0 で途切れる。外側の領域の値が内側へ漏れることはない |

## 導入時の推奨事項

### 左右のパディングは、同じ要素に同じ値で指定する

- `padding: 0 16px` のように指定する。
- 左のパディングを外側の枠に、右のパディングをスクロール領域に指定すると、見た目は同じでも判定が分かれる。

### スクロールバーのために、右のパディングを別に足さない

- `padding-right: 17px` のような値は、スクロールバー用なのかデザイン上のパディングなのか判別できないので、このライブラリは取り除かない。
- スクロールバーが現れたときにずれるのは補正するが、スクロールバーがないときに右が広く見えるのは残る。
- その値を消せば、自動で合う。

### スクロールバーの場所を、あらかじめ確保しない

- 確保してあるもの（`scrollbar-gutter`）は、可能な場合には解除する。
- それでも、最初からない方が結果は明確である。

### スクロールバーの幅を測ってパディングを直す自前のスクリプトがあれば、取り外す

- 二つの仕組みが、同じパディングを扱うことになる。
- このライブラリが元のスクロールバーを隠した後も、そのスクリプトが測っておいた値が残り、パディングがもう一度入る（テストで、左のパディングがスクロールバーの幅の分だけ余計に入ることを確認した）。
- 取り外せないときは、その領域に `data-scrollbar="off"` を付ける。
