## トラブルシューティング

### デバッグ表示で見る

「何をしたのかが見えない」ことが、最も大きな不安である。`debug` をオンにすると、二つのものが生まれる — 画面に描かれるものと、領域に付く属性である。

#### 画面に描かれるもの

手を加えた、または加えようとしてできなかったスクロール領域ごとに、次のものが重ねて描かれる。色は方式ごとに決まっている。

| 描かれるもの | 意味 |
| --- | --- |
| 太い枠線と薄い塗り | そのスクロール領域 |
| 濃い帯 | スクロールバーが置かれた場所 — 自身のパディング・中央寄せ・重ねるは領域の内側の端、外側に浮かせるは領域の外 |
| 斜線の帯 | 減らしたり足したりした後のパディング。領域自身ではなく内側の子要素のパディングを変えた場合は、その子要素の位置に描かれる |
| 点線の四角形 | スクロールバーがないときの内容の位置。スクロールバーが現れても、内容がこの中にそのまま収まっていれば、ずれていない |
| 左上のラベル | 縦（`↕`）・横（`↔`）に選んだ方式、スクロールバーの太さ（`S`・`H`）、外側に浮かせるときに離した距離（`gap`）、変更した値の前 → 後、理由 |

ラベルの例:

| ラベル | 読み方 |
| --- | --- |
| `↕ padding · S 11 · padding-right 24 → 13` | 縦スクロールバー（11px）を、自身のパディングで受けた。右のパディングを 24 から 13 に減らした |
| `↕ center · S 11 · padding-left 0 → 11` | 中央寄せで受けた。左に 11 を足した |
| `↕ center · S 11 · child padding-right 16 → 5` | 幅いっぱいの内側の子要素の、右のパディングを減らした |
| `↕ outside · S 11 · gap 2` | 外側に浮かせた。枠線 2px を越えて、領域から 2px 離れた場所である |
| `↕ overlay · S 11 — outside-occupied` | 内容の上に重ねた。外側の場所に別の要素があるためである |
| `↕ outside · S 11 · ↔ overlay · H 11` | 縦は外側、横は内容の上 |

知っておくこと:

- 画面の最上部に別に浮かせたレイヤーに描く。スクロール領域の中には何も差し込まず、クリックも横取りしない。
- 手を加える必要がなかった領域（スクロールバーがない・オフにしている・除外している）は描かない。そのような領域にも、下の属性は付く。
- レイヤーが最上部にあるため、固定されたヘッダーの下に潜り込んだ領域の枠線が、ヘッダーの上に見えることがある。
- ラベルは文字の長さのままに描かれるので、狭い領域では領域の外にはみ出すことがある。
- 領域の中に領域があると、帯と点線が重なって見える。
- スクロールバーが現れてはじめて、描くものが生まれる。内容があふれない領域は、表示がないのが正常である。

#### 領域に付く属性

開発者ツールでその領域を選ぶと見える。テストの中で読んで使うこともできる。

| 属性 | 意味 |
| --- | --- |
| `data-scrollbar-method` | 縦スクロールバーに選んだ方式 |
| `data-scrollbar-method-x` | 横スクロールバーに選んだ方式 |
| `data-scrollbar-why` | その方式になった理由 — より前の方式を使えなかった理由（下の「理由」の表） |

方式:

| 方式 | 意味 | 色 |
| --- | --- | --- |
| `padding` | 1 自身のパディングを減らした | 緑 |
| `center` | 2 中央寄せで受けた | 青 |
| `outside` | 3 外側に浮かせた | 紫 |
| `overlay` | 4 内容の上に重ねた | オレンジ |
| `widen` | 予備の方式で領域を広げた | 黄 |
| `manual` | `manual` 設定なので、幅だけを渡した | 黒 |
| `none` | 何もしなかった | 灰色の点線（理由が「手を加える必要なし」なら描かない） |

理由 — 手を加える必要がなかった:

| 理由 | 意味 |
| --- | --- |
| `no-scrollbar` | スクロールバーが表示されていない（あふれていないか、オーバーレイスクロールバーの環境である） |
| `nothing-to-scroll` | スクロールバーは常に表示する設定だが、スクロールするものがない — 何も浮かせなかった |
| `off` · `excluded` | `data-scrollbar="off"` が付いている · `exclude` セレクタに該当した |

理由 — 外側に浮かせられなかった:

| 理由 | 意味 |
| --- | --- |
| `outside-too-narrow` | 外側の余白・空きが、スクロールバーの幅より狭い |
| `outside-occupied` | スクロールバーが置かれる場所に、別の要素がある（隣のパネル、余白の中のボタン） |
| `outside-behind-box` | 外側に空きはあるが、間に背景・枠線のあるボックスや、あふれた部分を切り取る枠がある |
| `outside-gap-over-limit` | 越える必要のある枠線の太さの合計が、`stayClose` を超える |
| `outside-is-scroller` | 外側の枠が、それ自体スクロール領域である |
| `outside-none` | ドキュメントの端まで上っても、使える余白がない |
| `outside-clipped-or-unanchored` | 外側に浮かせてみたが、祖先に切り取られて見えないか、所定の位置に付かなかった |
| `no-anchor-positioning` | ブラウザに anchor positioning がない |
| `page-has-no-outside` | ページ全体（ブラウザウィンドウ）のスクロールなので、外側がない |

理由 — そのほか:

| 理由 | 意味 |
| --- | --- |
| `cannot-attach` | スクロールバーを浮かせられない要素である（`ul`・`table`・`textarea`、Web コンポーネントのタグ、すでに shadow root がある要素） |
| `cannot-overlay` | 重ねることもできない構造である（横にあふれるのに、横スクロールバーを浮かせられない場合など） |
| `center-too-narrow` | 中央寄せだが、左右の空きがスクロールバーより狭いので、内容の上に重ねた |
| `center-not-applicable` | `center` 設定だが、中央寄せで受けられない構造である |
| `gutter-kept` · `gutter-released` | 確保されたスクロールバーの場所を解除するとずれるので、そのままにした · 場所だけを解除した（今はスクロールバーがない） |

### 症状別

#### コンソールやエラー収集ツールに `ResizeObserver loop completed with undelivered notifications` が出力される

- **原因**: スクロールバーが現れたのを検知したその場でパディングを直すために、ブラウザが出す通知である。動作には問題がない。
- **対処**: デフォルトでは、このライブラリがその通知を横取りして、後から登録されたリスナーに届かないようにする（`quiet`）。先に登録されたリスナー（開発サーバーのエラー表示など）には、見えることがある。

#### スクロールバーが細く、手を離すと消える。このライブラリが動いていないようだ

- **原因**: オーバーレイスクロールバーの環境である。ずれがないので、することがない。
- **対処**: 幅を取るスクロールバーで見るには、OS の設定でスクロールバーの表示を「常に」に変える。

#### 外側に余白があるのに、スクロールバーが内容の上に重なる

- **原因**（四つのうちのいずれか）:
  - 外側の余白が、スクロールバーの幅より狭い。
  - 領域のすぐ隣に、別の要素が接している。
  - その余白の中の、スクロールバーが置かれる場所に、別の要素（閉じるボタンなど）が浮いている。
  - 余白ではなく空きの側だが、間に枠線・背景のあるボックスが挟まっている。
- **対処**: `debug` をオンにして、その領域の `data-scrollbar-why` を見る。外側の余白をスクロールバーの幅以上にするか、スクロール領域自身にパディングを持たせる。

#### スクロールバーがないとき、右が左より広い

- **原因**: スクロールバー用に入れてあった右のパディングが残っている。
- **対処**: そのパディングを消す（[導入時の推奨事項](./configuration.md#導入時の推奨事項)）。

#### 常に表示しているスクロールバーが、内容が短いと見えない

- **原因**: 意図した動作である。スクロールするものがなければ、スクロールバーを浮かせない。
- **対処**: 常に見えている必要があれば、その領域に `data-scrollbar="off"` を付ける。

#### テキストエリア（`textarea`）で文字がずれる

- **原因**: テキストエリアは、デフォルトでは対象にしない。オプションをオンにしてもずれるなら、次の二つのいずれかである（デバッグ表示の理由が `cannot-attach`）。
  - テキストエリアの右のパディングが、スクロールバーの幅より狭い。
  - 幅を `box-sizing: content-box`（ブラウザのデフォルト）で固定したテキストエリアである。パディングを減らしても、文字幅は増えない。
- **対処**: `textarea` オプションをオンにする。テキストエリアの左右のパディングをスクロールバーの幅以上にして、`box-sizing: border-box` を指定する。または `data-scrollbar="manual"` で幅を受け取って、自分で合わせる（[設定](./configuration.md#オプション)）。

#### 特定の領域だけオフにしたい

- **対処**: その領域に `data-scrollbar="off"` を付ける。

## 制約事項

### 環境

**オーバーレイスクロールバーの環境では何もしない。**

- Mac のデフォルト設定やモバイルのように、スクロールバーが幅を取らなければ（測った幅が 0）、そもそもずれは起きない。

**子要素を上から下へ積まない領域（グリッド・横並び・逆向きの積み）での重ねは、anchor positioning が必要である。**

- ないブラウザでは、そのような領域を重ねるで受けられないので、手を加えない。

### 手を加えないもの

**数値で指定した右のパディングは直さない。**

- [導入時の推奨事項](./configuration.md#導入時の推奨事項)を参照。

**対象にしない領域がある。**

- shadow root の中、iframe の中のスクロール領域。
- テキストエリア（`textarea`）は、`textarea` オプションをオンにしたときだけ対象になる。オンにしても、スクロールバーを浮かせることはできない（パディングを減らすことと `manual` だけができる）。
- `exclude` に該当した区域。

**サイズを保てないボックスには、パディングを減らす方式を使わない。**

- サイズを内側の内容基準（`box-sizing: content-box`）で固定したボックスは、パディングを減らすと、文字の領域はそのままでボックスだけが縮む。
- そのようなボックスでは 1番・2番を飛ばして、次の順序（外側に浮かせる・重ねる）に移る。幅・高さを書き換えて合わせることはしない。
- スクロールバーを浮かせられない要素（テキストエリアなど）がそのようなボックスなら、受ける方法がないので、そのままにする。`box-sizing: border-box` を指定すれば受けられる。

**ページ全体（ブラウザウィンドウ）の横スクロールバーは扱わない。**

### スクロールバーを浮かせるとき

**shadow root は元に戻せない。**

- スクロールバーを浮かせた領域（外側に浮かせる・重ねる）には、shadow root を付ける。一度付けた shadow root は、取り外す方法がない。
- このライブラリを取り外した後も、その要素の `shadowRoot` は残る（中のスクロールバーは隠す）。
- そのため、**その要素に後から `attachShadow` を呼ぶコードは、例外になる。**
- 最も引っかかりやすいのは、定義が遅れて読み込まれる Web コンポーネントである。そのため、Web コンポーネントのタグ（名前に `-` を含むタグ）には shadow root を付けない — そのようなスクロール領域は、下の「スクロールバーを浮かせられない要素」と同じに扱う。
- 通常のタグで、後から shadow root を付けるコードがあるなら、その要素に `data-scrollbar="off"` か `manual` を付けて、スクロールバーを浮かせないようにする。
- パディングを減らす方式・中央寄せで受ける領域には、shadow root を付けない。

**スクロールバーを浮かせられない要素がある。**

- 浮かせたスクロールバーは、スクロール要素の shadow root に置く。
- 該当する要素: shadow root を付けられないタグ（`ul`・`table`・`textarea` など）、すでに shadow root がある要素、Web コンポーネントのタグ。
- このような要素には、1番・2番だけが適用される。
- 外側に場所があり、その領域が目に見えるボックス（枠線・背景）でなければ、予備の方式で領域を `S` の分だけ広げる。
- それもできなければ、手を加えない（スクロールバーが現れたときにずれる）。
- そのような領域は、`manual` で自分で受けられる。

**浮かせたスクロールバーが置かれた場所へのクリックは、スクロールバーが受ける。**

- 目にはつまみだけが見えるが、スクロールバーの幅の分の帯全体がクリックを受ける。
- 重ねるでは、内容の右端（横は下端）のその幅の分が該当する。

**浮かせたスクロールバーを切り取るカードの中の領域と、自身が切り抜く領域は、外側に浮かせられない。**

- 該当するカード: あふれた部分を切り取りつつ `transform`・`filter`・`backdrop-filter` のようなものがかかったカード、形に切り抜く（`clip-path`）か、マスク（`mask`）をかけたカード。
- 外側に場所があっても、内容の上に重なる。
- 実際には切り取られないのに、切り取られると見なす場合もある（ページ全体をスクロールできないようにロックしてある画面など）。そのときも、重ねるに移る。

**スクロールバーを常に表示する設定は、「スクロールするものがあるときだけ見える」ものに変わる。**

- `overflow: scroll` で常に見えるようにしてある空のスクロールバーは、内容があふれなければ見えない（[動作の仕組み](./how-it-works.md#そのほかにすること)）。

**縦・横の両方を内容の上に浮かせると、つまみが重なることがある。**

- 右下の角で、二つのつまみが重なることがある。

**より大きなスクロール領域の中で半分隠れた領域は、スクロールバーが外に見えることがある。**

- 外側に浮かせたスクロールバーが、その大きな領域の外に見えることがある（すべて隠れれば隠れる）。

### 再判定

**要素の変化がなく見た目だけが変わる場合は、すぐには捉えられない。**

- 該当する場合: マウスを乗せたときだけ広がる要素、アニメーション、遅れて適用されたフォント。
- 次にその領域をスクロールしたり、ウィンドウサイズを変えたりしたときに、正される。

**外側の空きに浮かせた領域は、その場所の周りの要素をすべて監視する。**

- 監視するもの: 空きを判定した枠と、そのすぐ下の子要素たち。
- 子要素が非常に多い枠では、監視する数もその分増える。

### 名前と表示

**`--sbw`・`--sbh` は、このライブラリが使う名前である。**

- スクロール領域ごとにインラインで書き込み（`manual` でなければ `0px`）、取り外すときに消す。
- アプリが同じ名前の変数をインラインで直接使うと、上書きされるか消される。

**デバッグ表示の描画は、拡大・縮小がかかった祖先の下でずれることがある。**

- 拡大・縮小（`transform: scale`）がかかった祖先の下では、帯の太さと位置がずれることがある。
- 表示だけが誤っていて、判定はそのままである。

### 判定の限界

**すべての構造で同じ結果になることは保証しない。**

- 判定は、画面に描かれたサイズ・余白を測って行う推定である。
- まれな構造では、方式を誤って選ぶことがある。
- そのような領域は、[領域ごとの設定](./configuration.md#領域ごとの設定)で正す。

## 検証状況

### 概要

| 項目 | 状態 |
| --- | --- |
| 適用範囲 | パッケージとして切り出す前の同じコードを、あるサービスのアプリ2つに適用して使っている |
| 自動テスト | `npm test` — ビルドした成果物（`dist`）をプレイグラウンド（`playground/`）につないで、Playwright で3つのエンジンで実行する |
| 最後の結果 | 2026-11-20、126件が成功 · 21件は、そのエンジンでスクロールバーの幅を作れないためスキップ |
| テスト対象 | テスト画面（`playground/bench.html`）のケース39件と、他のプロジェクトを模したページ12件（スクロール領域60か所あまり） |
| 実際のアプリ画面 | パッケージとして切り出す直前のコードで、Chrome（Mac）、スクロールバー 11px、ウィンドウ幅 2025 で 2026-11-20 に測った — 画面46件とモーダル4種の縦スクロール領域120か所あまりで、スクロールバー前後の内容の移動は 0（最大 0.1px）。横スクロール領域と狭いウィンドウ（1024・390）は、アプリ画面では測っていない |
| 保留 | 画面の一部（コンテナ一つ）だけをオンにするオプション — モーダル・ドロップダウンがそのコンテナの外に描画される問題があるため、見送った。アプリ・ページ単位は、コンポーネントを置く場所ですでにできる |

### 確認した環境

| エンジン | 確認したスクロールバー | 備考 |
| --- | --- | --- |
| Chromium | デフォルト 15px、細い（thin）11px、装飾したスクロールバー（`::-webkit-scrollbar`）11px・17px | — |
| Firefox | デフォルト 15px、細い 11px | ウィンドウを表示して実行した — ウィンドウなしで起動すると、スクロールバーの幅が 0 になる |
| WebKit（Safari のエンジン） | 装飾したスクロールバー 11px・17px | デフォルトのスクロールバーはオーバーレイ方式（幅 0）なので、「何もしない」ことだけを確認した |

### 確認できていないこと

- 実際の Windows（17px は、装飾したスクロールバーで模した）
- Safari で、デフォルトのスクロールバーが幅を取る設定
- Safari 26 そのもの（Playwright の WebKit は、同じエンジンの別ビルドである）— 自動テストでは動かせない。Safari 26.3 で、デモ画面の「外側に浮かせる」場面だけを人が直接確認した。その際、テスト用 WebKit では出なかった問題（浮かせた直後のスクロールバーの位置が次の画面更新でようやく決まる）を1つ見つけて修正した
- anchor positioning がない古いブラウザ

### テストが検証していること

ずれと方式:

- スクロールバーが現れる前後の内容の位置（ずれ 0）
- ケースごとに選んだ方式
- スクロールバーの幅が 0 のとき、何もしないか
- サイズを内側の内容基準で固定したボックスの幅・高さがそのままで、幅・高さを書き換えていないか
- 高さが内容で決まるボックスと、幅を割合で指定したボックスのサイズを、数値で固定していないか（行が増えたり、囲む枠が縮んだりしたら、追従するか）
- 幅いっぱいの `content-box` の子要素の文字幅がそのままか
- 予備の方式（広げる）が、`content-box` のリストをスクロールバーの幅の分だけ広げるか

浮かせたスクロールバー:

- 浮かせたスクロールバーが所定の位置で捉えられ、画面に実際に描画されるか
- 内容とつまみのスクロールの連動
- スクロールするものがないとき、クリックを横取りするバーがないか
- 浮かせたバーの上でのホイールがスクロール領域に渡り、Ctrl+ホイールは渡さないか
- Web コンポーネントのタグに shadow root を付けないか

再判定と元に戻す:

- 隣の要素が広がったり狭まったりするとき、再判定するか
- 入れ子の二つの領域が同じ瞬間に再判定されても、互いのスクロールバーが重ならないか
- スクロールバーが消えた後と、このライブラリを取り外した後に、痕跡がないか

オプション:

- `stayClose` — 上限のデフォルト値と、違う値
- `exclude` — 除外した区域はそのままで、それ以外は処理されるか
- `debug` — デバッグ表示が実際に選んだ方式と同じか、オフにすると消えるか、デバッグをオンにしても選ばれる方式が同じか
- `quiet` — ブラウザの通知を横取りするデフォルトと、オフにした場合
- `textarea` — デフォルトではテキストエリアをそのままにするか（他の領域を幅いっぱいに埋める子要素のときも）、オンにするとパディングを減らして文字幅がそのままか、パディングが狭いテキストエリアはそのままにするか、常に表示するスクロールバーのテキストエリアに文章を入れても、スクロールバーが隠れないか、取り外すと元に戻るか

デバッグ表示のレイヤー:

- ラベルにスクロールバーの太さと変更した値が書かれるか
- スクロールバーの場所を示す帯の太さが、元のスクロールバーと同じか
- 内容の位置を示す点線が、実際に内容が置かれた場所と同じか
- クリックを横取りしないか

組み込み:

- React なしで本体だけを読み込んで、組み込みと取り外しができるか
- 本体が React を読み込まないか
- 使えない環境で組み込んでも例外が出ず、その後の組み込み・取り外しが正常か
