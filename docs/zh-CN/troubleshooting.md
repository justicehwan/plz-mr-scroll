## 问题排查

### 通过调试显示查看

最大的不安是“看不到它做了什么”。开启 `debug` 后会出现两样东西：画在页面上的图形，和加在区域上的属性。

#### 页面上画出的内容

对每个处理过、或想处理却没能处理的滚动区域，都会叠加画出下列内容。颜色按方式区分。

| 画出的内容 | 含义 |
| --- | --- |
| 粗边框和浅色填充 | 该滚动区域 |
| 深色条带 | 滚动条所在位置——自身内边距、居中、叠放在区域内侧边缘，浮到外侧则在区域外 |
| 斜线条带 | 缩小或增加之后的内边距。如果改的不是区域自身、而是内部子元素的内边距，就画在那个子元素的位置上 |
| 虚线矩形 | 没有滚动条时内容所在的位置。滚动条出现后内容仍在这个框内，就说明没有被挤开 |
| 左上角的标签 | 纵向（`↕`）、横向（`↔`）选用的方式，滚动条粗细（`S`、`H`），浮到外侧时拉开的距离（`gap`），改动值的前 → 后，以及原因 |

标签示例：

| 标签 | 读法 |
| --- | --- |
| `↕ padding · S 11 · padding-right 24 → 13` | 纵向滚动条（11px）用自身内边距处理。右内边距从 24 缩小到 13 |
| `↕ center · S 11 · padding-left 0 → 11` | 用居中处理。左侧加了 11 |
| `↕ center · S 11 · child padding-right 16 → 5` | 缩小了撑满宽度的内部子元素的右内边距 |
| `↕ outside · S 11 · gap 2` | 浮到了外侧。越过 2px 的边框，距离区域 2px |
| `↕ overlay · S 11 — outside-occupied` | 叠放在内容之上。因为外侧位置上有其他元素 |
| `↕ outside · S 11 · ↔ overlay · H 11` | 纵向在外侧，横向在内容之上 |

须知：

- 画在页面最上方单独浮起的图层里。不会往滚动区域里插入任何东西，也不拦截点击。
- 无需处理的区域（没有滚动条、已关闭、已排除）不画。这类区域同样会加上下面的属性。
- 由于图层在最上方，滚到固定页头下面的区域，其边框可能会显示在页头之上。
- 标签按文字长度绘制，在较窄的区域里可能会超出区域。
- 区域里还有区域时，条带和虚线会重叠显示。
- 有滚动条才有东西可画。内容没有溢出的区域没有显示是正常的。

#### 加在区域上的属性

在开发者工具里选中该区域就能看到。也可以在测试中读取使用。

| 属性 | 含义 |
| --- | --- |
| `data-scrollbar-method` | 纵向滚动条选用的方式 |
| `data-scrollbar-method-x` | 横向滚动条选用的方式 |
| `data-scrollbar-why` | 选用该方式的原因——更靠前的方式为什么用不了（见下方“原因”表） |

方式：

| 方式 | 含义 | 颜色 |
| --- | --- | --- |
| `padding` | 缩小了自身内边距（方式 1） | 绿色 |
| `center` | 用居中处理（方式 2） | 蓝色 |
| `outside` | 浮到了外侧（方式 3） | 紫色 |
| `overlay` | 叠放在了内容之上（方式 4） | 橙色 |
| `widen` | 用备用方式把区域加宽了 | 黄色 |
| `manual` | 因为是 `manual` 设置，只提供了宽度 | 黑色 |
| `none` | 什么都没做 | 灰色虚线（原因是“无需处理”时不画） |

原因——无需处理：

| 原因 | 含义 |
| --- | --- |
| `no-scrollbar` | 没有显示滚动条（没有溢出，或处于悬浮式滚动条环境） |
| `nothing-to-scroll` | 滚动条被设为始终显示，但没有可滚动的内容——什么都没有浮出 |
| `off` · `excluded` | 加了 `data-scrollbar="off"` · 匹配了 `exclude` 选择器 |

原因——没能浮到外侧：

| 原因 | 含义 |
| --- | --- |
| `outside-too-narrow` | 外侧留白或空位比滚动条宽度窄 |
| `outside-occupied` | 滚动条要站的位置上有其他元素（旁边的面板、留白里的按钮） |
| `outside-behind-box` | 外侧有空位，但中间隔着有背景或边框的盒子，或裁剪溢出部分的容器 |
| `outside-gap-over-limit` | 需要越过的边框厚度之和超过了 `stayClose` |
| `outside-is-scroller` | 外层容器本身就是滚动区域 |
| `outside-none` | 一路向上直到文档顶端，也没有可用的留白 |
| `outside-clipped-or-unanchored` | 试着浮到外侧，但被祖先元素裁掉看不见，或者没有贴在原位 |
| `no-anchor-positioning` | 浏览器不支持 anchor positioning |
| `page-has-no-outside` | 整页（浏览器窗口）滚动，没有外侧 |

原因——其他：

| 原因 | 含义 |
| --- | --- |
| `cannot-attach` | 无法浮出滚动条的元素（`ul`、`table`、`textarea`，Web Component 标签，已有 shadow root 的元素） |
| `cannot-overlay` | 连叠放也做不了的结构（横向溢出但无法浮出横向滚动条等情况） |
| `center-too-narrow` | 是居中结构，但左右空白比滚动条窄，所以叠放在了内容之上 |
| `center-not-applicable` | 设置了 `center`，但结构无法按居中处理 |
| `gutter-kept` · `gutter-released` | 解除预留的滚动条位置会导致内容被挤开，所以保持原样 · 只解除了预留的位置（当前没有滚动条） |

### 按症状

#### 控制台或错误收集工具里出现 `ResizeObserver loop completed with undelivered notifications`

- **原因**：本库在察觉滚动条出现的当下就修改内边距，浏览器因此留下这条提示。不影响功能。
- **处理**：默认情况下，本库会拦截该提示，使它传不到之后注册的监听器（`quiet`）。更早注册的监听器（如开发服务器的错误提示）仍可能看到它。

#### 滚动条很细，松开手就消失，本库好像没在运行

- **原因**：处于悬浮式滚动条环境。没有挤开问题，本库无事可做。
- **处理**：想看到占宽度的滚动条，就在操作系统设置里把滚动条显示改为“始终”。

#### 外侧明明有留白，滚动条却叠在内容上

- **原因**（以下四种之一）：
  - 外侧留白比滚动条宽度窄。
  - 区域紧旁边贴着其他元素。
  - 在那段留白里、滚动条要站的位置上，浮着其他元素（如关闭按钮）。
  - 不是留白、而是空位的情况，但中间夹着有边框或背景的盒子。
- **处理**：开启 `debug`，查看该区域的 `data-scrollbar-why`。把外侧留白设为不小于滚动条宽度，或者给滚动区域自身加内边距。

#### 没有滚动条时右侧比左侧宽

- **原因**：为滚动条加的右内边距还留着。
- **处理**：删掉这段内边距（[使用建议](./configuration.md#使用建议)）。

#### 始终显示的滚动条在内容很短时不见了

- **原因**：这是预期行为。没有可滚动的内容时，不浮出滚动条。
- **处理**：必须一直显示的话，给该区域加 `data-scrollbar="off"`。

#### 文本框（`textarea`）里的文字被挤开

- **原因**：文本框默认不处理。已经开启选项还是被挤开，则是下面两种情况之一（调试显示的原因为 `cannot-attach`）。
  - 文本框的右内边距比滚动条宽度窄。
  - 按 `box-sizing: content-box`（浏览器默认值）写死了宽度的文本框。缩小内边距，文字宽度也不会增加。
- **处理**：开启 `textarea` 选项。把文本框的左右内边距设为不小于滚动条宽度，并设置 `box-sizing: border-box`。或者用 `data-scrollbar="manual"` 接收宽度并自行调整（[配置](./configuration.md#选项)）。

#### 只想关掉某个区域

- **处理**：给该区域加 `data-scrollbar="off"`。

## 限制

### 环境

**悬浮式滚动条环境下什么都不做。**

- 像 Mac 默认设置或移动端那样，滚动条不占宽度（实测宽度为 0）时，本来就不存在挤开问题。

**子元素不是自上而下堆叠的区域（网格、横向排列、反向堆叠）要叠放，必须支持 anchor positioning。**

- 不支持的浏览器无法用叠放处理这类区域，所以不去动它们。

### 不处理的内容

**不会改你写成具体数值的右内边距。**

- 参见[使用建议](./configuration.md#使用建议)。

**有些区域不处理。**

- shadow root 内部、iframe 内部的滚动区域。
- 文本框（`textarea`）需要开启 `textarea` 选项才会处理。开启后也无法浮出滚动条（只能缩小内边距和使用 `manual`）。
- 匹配 `exclude` 的区域。

**对无法保持尺寸的盒子，不使用缩小内边距的方式。**

- 按内部内容为基准（`box-sizing: content-box`）写死尺寸的盒子，缩小内边距后，文字区域不变，只有盒子变窄。
- 这类盒子会跳过方式 1、2，直接转到后面的方式（浮到外侧、叠放）。不会靠改写宽度和高度来凑。
- 如果无法浮出滚动条的元素（如文本框）恰好是这种盒子，就没有办法处理，只能保持原样。设置 `box-sizing: border-box` 后即可处理。

**不处理整页（浏览器窗口）的横向滚动条。**

### 浮出滚动条时

**shadow root 无法还原。**

- 浮出了滚动条的区域（浮到外侧、叠放）会被挂上 shadow root。shadow root 一旦挂上，就没有办法摘除。
- 本库卸载之后，该元素的 `shadowRoot` 依然存在（其中的滚动条会被隐藏）。
- 因此，**之后对该元素调用 `attachShadow` 的代码会抛出异常。**
- 最容易碰到的是定义被延迟加载的 Web Component。所以不会给 Web Component 标签（名称里带 `-` 的标签）挂 shadow root——这类滚动区域按下面“无法浮出滚动条的元素”的方式处理。
- 如果是普通标签、但之后有代码要给它挂 shadow root，就给该元素加 `data-scrollbar="off"` 或 `manual`，让它不浮出滚动条。
- 以缩小内边距或居中方式处理的区域，不会挂 shadow root。

**有些元素无法浮出滚动条。**

- 浮出的滚动条放在滚动元素的 shadow root 里。
- 涉及的元素：不能挂 shadow root 的标签（`ul`、`table`、`textarea` 等）、已经有 shadow root 的元素、Web Component 标签。
- 这类元素只适用方式 1、2。
- 外侧有位置、且该区域不是可见的盒子（没有边框、背景）时，用备用方式把区域加宽 `S`。
- 这也不行的话就不处理（滚动条出现时内容会被挤开）。
- 这类区域可以用 `manual` 自己处理。

**浮出的滚动条所在位置的点击由滚动条接收。**

- 肉眼只看到滑块，但与滚动条同宽的整条区域都会接收点击。
- 叠放时，指内容右端（横向则是下端）与滚动条同宽的那一条。

**会裁掉浮出滚动条的卡片里的区域，以及自己裁剪自身的区域，无法浮到外侧。**

- 涉及的卡片：裁剪溢出部分、同时设置了 `transform`、`filter`、`backdrop-filter` 之类的卡片，按形状裁剪（`clip-path`）或加了遮罩（`mask`）的卡片。
- 即使外侧有位置，也会叠放在内容之上。
- 也有实际上不会被裁、却被判断为会被裁的情况（比如锁定整页滚动的界面）。这时同样转为叠放。

**始终显示滚动条的设置，会变成“只在有东西可滚动时才显示”。**

- 用 `overflow: scroll` 设成始终显示的空滚动条，内容没有溢出时就不显示（[工作原理](./how-it-works.md#其他处理)）。

**纵向、横向都浮在内容之上时，滑块可能重叠。**

- 两个滑块可能在右下角重叠。

**在更大的滚动区域里被遮住一半的区域，滚动条可能会露在外面。**

- 浮到外侧的滚动条可能显示在那个大区域之外（完全被遮住时则隐藏）。

### 重新判定

**元素没有变化、只是外观变了的情况，无法立即捕捉。**

- 涉及的情况：只在鼠标悬停时变宽的元素、动画、延迟生效的字体。
- 下次滚动该区域或调整窗口尺寸时会被纠正。

**浮到外侧空位的区域，会监视那个空位周围的全部元素。**

- 监视的对象：判定出空位的容器，及其紧邻的下一级子元素。
- 容器的子元素非常多时，监视的数量也相应增加。

### 名称与显示

**`--sbw`、`--sbh` 是本库使用的名称。**

- 每个滚动区域都以内联方式写入（不是 `manual` 时为 `0px`），卸载时清除。
- 应用如果自己以内联方式写了同名变量，就会被覆盖或清除。

**调试显示的图形在设置了缩放的祖先元素之下可能错位。**

- 在设置了缩放（`transform: scale`）的祖先元素之下，条带的粗细和位置可能错位。
- 只是显示不对，判定本身不受影响。

### 判定的局限

**不保证所有结构都得到同样的结果。**

- 判定是通过测量渲染出的尺寸和内边距做出的推断。
- 在少见的结构中可能选错方式。
- 这类区域用[按区域设置](./configuration.md#按区域设置)来纠正。

## 验证情况

### 一览

| 项目 | 状态 |
| --- | --- |
| 使用范围 | 在拆分成独立包之前，同一份代码已应用于同一服务的 2 个应用，并在使用中 |
| 自动化测试 | `npm test`——把构建产物（`dist`）接到 playground（试验场，`playground/`）上，用 Playwright 在三个引擎上运行 |
| 最近结果 | 2026-11-20，126 项通过 · 21 项因该引擎无法产生滚动条宽度而跳过 |
| 测试对象 | 测试页（`playground/bench.html`）上的 39 个用例，以及模仿其他项目的 12 个页面（60 多个滚动区域） |
| 真实应用页面 | 使用拆分成独立包之前的代码，在 Chrome（Mac）、滚动条 11px、窗口宽度 2025 的条件下，于 2026-11-20 测量——46 个页面和 4 种模态框中 120 多个纵向滚动区域，滚动条出现前后内容位移为 0（最大 0.1px）。横向滚动区域和窄窗口（1024、390）没有在应用页面上测量 |
| 搁置 | 只对页面一部分（单个容器）开启的选项——模态框、下拉菜单会渲染到该容器之外，存在这个问题，所以推迟了。应用或页面级别已经可以通过放置组件的位置实现 |

### 已验证的环境

| 引擎 | 已验证的滚动条 | 备注 |
| --- | --- | --- |
| Chromium | 默认 15px，细（thin）11px，自定义样式滚动条（`::-webkit-scrollbar`）11px、17px | — |
| Firefox | 默认 15px，细 11px | 带窗口运行——无窗口运行时滚动条宽度为 0 |
| WebKit（Safari 引擎） | 自定义样式滚动条 11px、17px | 默认滚动条是悬浮式（宽度 0），所以只验证了“什么都不做” |

### 未验证的内容

- 真实的 Windows（17px 是用自定义样式滚动条模拟的）
- Safari 中默认滚动条占宽度的设置
- Safari 26 本身（Playwright 的 WebKit 是同一引擎的另一个构建）
- 不支持 anchor positioning 的旧浏览器

### 测试断言的内容

挤开与方式：

- 滚动条出现前后的内容位置（挤开为 0）
- 各情形下选用的方式
- 滚动条宽度为 0 时是否什么都不做
- 按内部内容为基准写死尺寸的盒子，其宽度和高度是否保持不变，以及是否没有改写宽度和高度
- 高度由内容决定的盒子，和宽度按比例给出的盒子，其尺寸是否没有被固化成具体数值（行数增加或外层容器缩小时是否跟着变）
- 撑满宽度的 `content-box` 子元素，其文字宽度是否保持不变
- 备用方式（加宽）是否只把 `content-box` 列表加宽一个滚动条的宽度

浮出的滚动条：

- 浮出的滚动条是否贴在原位，并且真的画在了页面上
- 内容与滑块的滚动联动
- 没有可滚动内容时，是否没有拦截点击的滚动条
- 浮出滚动条上的滚轮是否传给滚动区域，而 Ctrl+滚轮是否不传
- 是否没有给 Web Component 标签挂 shadow root

重新判定与还原：

- 相邻元素变宽、变窄时是否重新判定
- 嵌套的两个区域在同一时刻重新判定时，彼此的滚动条是否不会重叠
- 滚动条消失之后、以及关闭本库之后，是否没有残留痕迹

选项：

- `stayClose`——默认限制值与其他取值
- `exclude`——被排除的区域是否保持原样，其余区域是否照常处理
- `debug`——调试显示是否与实际选用的方式一致、关闭后是否清除，以及开启调试后选用的方式是否不变
- `quiet`——拦截浏览器提示的默认情况，以及关闭的情况
- `textarea`——默认值下是否保持文本框原样（包括它是另一区域里撑满宽度的子元素时）、开启后是否缩小内边距且文字宽度不变、内边距窄的文本框是否保持原样、给始终显示滚动条的文本框输入文字后滚动条是否不会消失、卸载后是否还原

调试图层：

- 标签上是否写出滚动条粗细和改动值
- 滚动条位置条带的粗细是否与原生滚动条一致
- 内容位置的虚线是否与内容实际所在位置一致
- 是否不拦截点击

安装：

- 不带 React、只引入核心部分，能否安装和卸载
- 核心部分是否不会引入 React
- 在不可用的环境中安装是否不抛异常，之后的安装、卸载是否正常
