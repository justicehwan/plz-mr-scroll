## 功能一览

| 功能 | 说明 |
| --- | --- |
| 自动发现 | 通过计算样式找出页面上的纵向、横向滚动区域，不依赖 class 名称或 CSS 的写法。之后挂载的元素（模态框、下拉菜单）也能找到 |
| 按区域判定 | 不把同一种补偿原样套用到所有区域，而是根据区域结构，在四种方式中选一种（[自动判定的优先级](#自动判定的优先级)） |
| 纵向、横向分开 | 两个滚动条的位置分别确定 |
| 保留原生滚动条 | 使用浏览器原生滚动条，而不是自绘的。用 `scrollbar-width`、`scrollbar-color`、`::-webkit-scrollbar` 设置的样式也会沿用 |
| 实测滚动条宽度 | 不假设宽度，使用在当前浏览器中实测的值 |
| 重新判定 | 区域或内容的尺寸变化，或者元素、样式变化时，重新判定 |
| 还原 | 按元素记录改过的内边距、变量和标记，本库卸载时全部还原。唯独浮出滚动条的区域上挂的 shadow root 无法摘除，会保留下来（[限制](./troubleshooting.md#限制)） |
| 嵌套区域 | 滚动区域里还有滚动区域时，先判定外层，避免两者占用同一段内边距 |
| 设置 | 全局选项有五个（`stayClose`、`exclude`、`debug`、`quiet`、`textarea`），另有按区域添加的 `data-scrollbar`（关闭、固定方式、手动控制）。什么都不传也能工作 |
| 调试显示 | 开启后会在页面上画出每个区域做了什么：选用的方式和原因、滚动条所在位置、缩小或增加的内边距的前后值、没有滚动条时内容所在的位置 |

## 自动判定的优先级

这是本库的核心。

- 不用同一种办法补偿所有滚动条。
- 对每个出现滚动条的区域分析结构，采用**第一个适用的方式**。
- 下文中 `S` 表示在当前浏览器中实测的滚动条宽度。

### 纵向滚动条

| 顺序 | 区域的结构 | 做什么 | 会遮住内容吗 |
| --- | --- | --- | --- |
| 1 自身内边距 | 滚动区域自身的右内边距不小于 `S` | 把这段内边距缩小 `S`。滚动条就出现在腾出的位置上 | 不会 |
| 2 居中 | 内部内容左右两侧的空白相等（差值不超过 2px） | 在左侧加上 `S` | 不会 |
| 3 外侧留白 | 滚动区域的右边缘紧贴外层容器的内边距（不小于 `S`），或者右侧外面是空位 | 滚动区域保持不变，只把滚动条浮到区域紧外侧 | 不会 |
| 4 叠放 | 上面三种都不行 | 把滚动条浮在内容右端之上 | 只遮住滑块所在之处，且为半透明 |

### 各方式细节

#### 1 自身内边距

- **为什么需要它**：这是最常见的结构。变化止于区域内部，对外部没有影响。

#### 2 居中

- **为什么需要它**：居中的内容如果只缩小右侧，就不再居中；两侧保持一致，才不会偏离原位。

#### 1 和 2 不改变盒子的外部尺寸

- 按内部内容为基准（`box-sizing: content-box`）写死尺寸的盒子（如 `width: 240px`），只缩小内边距的话，文字区域不变，整个盒子反而变窄。
- 这类盒子不使用该方式，直接转到下一个顺序。横向滚动条的下内边距（高度）同理。
- 也不会靠改写宽度和高度来凑。那样会让按比例给出的尺寸固化成具体数值，也会把由内容决定的尺寸写死。
- 缩小撑满宽度的内部子元素的内边距时，标准相同——缩小后该子元素的文字区域若与没有滚动条时不一致，就不使用。
- 判断方法：分别测量没有滚动条时的尺寸和改动内边距之后的尺寸，看是否相同。只对 `content-box` 盒子测量。

#### 3 外侧留白

- **为什么需要它**：内边距在外层容器上而不在滚动区域上的结构（列表撑满容器）。区域自身没有可缩小的内边距。
- **有边框的盒子同样适用**：外侧有位置的话，就浮到边框紧外侧。
- **包裹的容器无论几层都能越过**：指无内边距地包着区域的容器（中间没有其他元素，只有边框）。
- **离得太远就不用**：越过的边框厚度之和超过 `stayClose`（默认 12px）时，转到方式 4。因为滚动条看起来会与自己的区域分离。

不用方式 3、转到方式 4 的情况：

| 情况 | 原因 |
| --- | --- |
| 滚动区域自身被按形状裁剪（`clip-path`）或加了遮罩（`mask`，如让上下边缘渐隐的效果） | 浮到区域外的滚动条会被区域自身裁掉而看不见 |
| 滚动条要站的位置上压着其他元素（如浮在内边距里的关闭按钮） | 避免浮出的滚动条盖住该元素、拦截点击 |

- 覆盖整个区域的背景、装饰层不算“占着那个位置的元素”。

#### 4 叠放

- **为什么需要它**：像每一行都铺满到边缘的列表、网格那样，哪里都没有位置的结构。与其挤开内容，不如选择浮在内容之上。
- **归到这里的布局**：子元素不是自上而下堆叠的布局（网格、横向排列、反向堆叠）也归到这里。
- **排在最后的原因**：会遮住内容的方式只有 4。

方式 4 也不会遮住滚动条的整个宽度。

- 浮出的滚动条背景（滑块移动的轨道）是透明的。
- 没有单独指定滑块颜色时，滑块也是半透明的（黑色 35%）。
- 所以被遮住的只有滑块所在的部分，而且那部分也能透出后面的内容。
- 如果页面代码里指定了滑块颜色（`scrollbar-color`、`::-webkit-scrollbar-thumb`），就直接使用该颜色。
- 不过，浮出的滚动条所在位置的点击由滚动条接收。

#### 3 和 4 单独浮出一个滚动条

- 把原来的滚动条隐藏，另外浮出一个外观相同的滚动条，并让两者的滚动位置联动。
- 浮出的这个也是浏览器原生滚动条，所以拖动、滚轮和外观都一样。

### 横向滚动条

与纵向分开判定。

| 顺序 | 区域的结构 | 做什么 |
| --- | --- | --- |
| 1 自身内边距 | 滚动区域自身的下内边距不小于滚动条高度 | 缩小这段内边距 |
| 2 外侧留白 | 外侧下方有外边距或空位 | 把滚动条浮到区域紧下方 |
| 3 叠放 | 前两种都不行 | 把滚动条浮在内容下沿之上（与纵向一样，背景透明） |

- 浏览器无法只隐藏纵向或横向其中一个滚动条。
- 因此只要浮出其中一个，原生滚动条就会两个都隐藏，并把两个都用浮出的滚动条画出来。
- 位置按轴分别确定——纵向可以在右侧外面，横向可以在内容之上。

## 其他处理

### 预留了滚动条位置的区域（`scrollbar-gutter: stable`）

- 只有解除后内容也不会被挤开时，才解除该设置，去掉空白条带。
- 可以解除的情况：能用上述某种方式处理，或者内容比区域宽、即使出现滚动条内容也不会移动。
- 其他情况不动它。

### 始终显示滚动条的区域（`overflow: scroll`）

- 与普通区域同样处理。
- 内容溢出时，用上述方式处理。
- 没有溢出时，隐藏原生滚动条的空白条带，也不浮出任何东西。无论是靠缩小内边距处理的结构，还是靠浮出处理的结构，都一样（文本框除外——见下文“文本框”）。
- 因此，“内容很短也一直显示的空滚动条”，变成只有在有东西可滚动时才显示。
- 两种情况下内容宽度相同。
- 这类区域每当内容增减，都会重新判定。

### 整页（浏览器窗口）滚动

- 纵向滚动条按同样的顺序处理。
- 没有外侧，所以跳过 3。
- 叠放时，浮在屏幕右端。

### 文本框（`textarea`）

- 默认不处理。只有打开 `textarea` 选项时才按同样的顺序处理（[配置](./configuration.md#选项)）。
- 文本框不能挂 shadow root，所以 3、4 不适用，只有 1（自身内边距）和 `manual` 可用。
- 文字增多、出现滚动条的那一刻进行判定，滚动条消失就还原。
- 对于始终显示滚动条（`overflow: scroll`）的文本框，不隐藏其空白条带。因为无法察觉文字变化导致溢出（只是值变了）。
- 没有打开该选项时，即使文本框是另一个滚动区域里撑满宽度的子元素，也不会动它的内边距。

### 嵌套区域

- 滚动区域里还有滚动区域时（包括整页之中的区域），先判定并应用外层，再判定内层。
- 这是为了避免内层区域再去占用外层区域为容纳自己的滚动条而缩小的内边距。

## 重新判定的时机

所有区域：

- 区域或其内容的尺寸变化时
- 元素被添加或移除，或 class、style、文字发生变化时
- 图片加载完成时
- 窗口尺寸变化时

浮到外侧空位的区域，还会监视空位周围元素的尺寸：

- 相邻元素变宽（哪怕只是边框、内边距增加）而占满那个位置时，改为叠放。
- 相邻元素尺寸不变、但挪到了那个位置（通过内联 style 移动，或动画结束后的位置）占住那里时，同样改为叠放。
- 位置重新空出来后，再回到外侧。

因动画进行中而没能浮到外侧的区域，会在动画结束时再试一次。

## 在页面上留下的内容

本库会在滚动区域及其周围的元素上写入下列内容。卸载时，除 shadow root 外，其余全部还原。

| 内容 | 位置 | 用途 |
| --- | --- | --- |
| 内联 style——`padding-right`、`padding-left`、`padding-bottom`、`margin-right`、`width`、`scrollbar-gutter` | 滚动区域、其内部的子元素、（备用方式下）外层容器 | 缩小和增加内边距。`margin-right`、`width` 只在备用方式（加宽）中使用 |
| CSS 变量 `--sbw`、`--sbh` | 滚动区域 | 页面代码在 `manual` 设置下读取 |
| 属性 `data-scrollbar-undo` | 改过上述 style 的元素 | 记录原始值 |
| 属性 `data-scrollbar-overlay` | 浮出了滚动条的区域（整页则为 `html`） | 隐藏原生滚动条 |
| shadow root | 浮出了滚动条的区域 | 把浮出的滚动条放在子元素列表之外。子元素通过 `<slot>` 照常显示。**本库卸载后依然保留**（只隐藏其中的滚动条） |
| 属性 `data-scrollbar-method`、`data-scrollbar-method-x`、`data-scrollbar-why` | 滚动区域 | 仅在开启 `debug` 时。记录选用的方式和原因 |
| 元素 `[data-scrollbar-debug]` | `body` 末尾 | 仅在开启 `debug` 时。绘制调试显示的图层——覆盖整个页面，但点击会穿透，图形画在该元素的 shadow root 里 |
| 属性 `data-scrollbar-nudge` | 浮出了滚动条的区域 | 重新判定时短暂加上再移除——为的是让 Safari 系浏览器重绘此前隐藏的滚动条 |
| 一个 `<style>` | `head` | 隐藏原生滚动条的规则 |
| `window` 上的一个 error 监听器 | — | 拦截“ResizeObserver loop”提示（仅在 `quiet` 为 `true` 时拦截） |
| 元素 `[data-scrollbar-ghost-page]` | `body` 末尾 | 整页浮出的滚动条 |

须知：

- **不动滚动区域的子元素列表。** 这是为了避免与 React 等框架管理的 DOM 冲突。
- 挂了 shadow root 的元素，外部 CSS 照常生效（子元素仍留在 light DOM 里）。
- 由于使用的是内联 style，如果有代码以内联方式直接修改同一属性，该值会被当作原始值。

## 浏览器支持

| 功能 | 需要 | 没有时 |
| --- | --- | --- |
| 自身内边距、居中、纵向叠放 | `ResizeObserver`、shadow DOM | — |
| 浮到外侧 · 浮出横向滚动条 · 网格和横向排列区域的叠放 | CSS anchor positioning——Chrome、Edge 125，Safari 26，Firefox 147 起 [1] | 纵向改用备用方式（把区域加宽 `S`）或叠放，横向保持原生滚动条。网格和横向排列的区域不处理 |

即使支持 anchor positioning，也可能因结构原因导致滚动条没能贴在原位。

- 例如：滚动区域自身设置了 `transform`、`filter`。
- 浮出后会立即测量位置；如果没有贴上，或被祖先元素裁掉看不见，该区域就按与不支持 anchor positioning 的浏览器相同的方式处理。
- 动画结束或窗口尺寸变化时会再试一次。

实际验证过的环境见[验证情况](./troubleshooting.md#验证情况)。
