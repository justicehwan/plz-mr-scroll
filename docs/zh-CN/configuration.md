## 作用范围：组件放在哪里，范围就在哪里

运行期间，本库处理整个页面（整个文档）的滚动区域。因此作用范围由放置位置决定（不用 React 时，则由何时安装、何时卸载决定）。

| 范围 | 放置位置 |
| --- | --- |
| 整个应用 | 应用最外层的布局 |
| 仅特定页面（路由） | 该页面或该组页面的布局。只在停留于这些页面时运行，离开后还原 |

- **渐进式引入**：先在一个页面上开启，再逐步扩大，就靠这种方式。
- **公共区域也会受影响**：开启期间，不仅页面正文，同时可见的公共区域（侧边栏、页头、模态框）也会生效。在开启和未开启的页面之间切换时，公共区域的滚动条外观可能会有差异。
- **不支持只开启一部分**：目前还没有只对页面一部分（单个容器）开启的选项。要**排除**一部分，用 `exclude`。

## 选项

所有选项都作用于整个页面。想让各区域各不相同，见[按区域设置](#按区域设置)。

| 选项 | 值 | 默认 | 含义 |
| --- | --- | --- | --- |
| `stayClose` | 数字（px） | `12` | 滚动条浮到外侧时，允许它与区域边缘拉开的最大距离 |
| `exclude` | CSS 选择器字符串 | 无 | 匹配该选择器的元素及其内部都不处理 |
| `debug` | 布尔值 | `false` | 开启调试显示——在页面上画出每个区域做了什么 |
| `quiet` | 布尔值 | `true` | 拦截浏览器产生的“ResizeObserver loop”提示 |
| `textarea` | 布尔值 | `false` | 同样处理文本框（`textarea`） |

```tsx
<MrScroll stayClose={4} exclude=".some-widget, .third-party" textarea debug />
```

```ts
installMrScroll({ stayClose: 4, exclude: ".some-widget, .third-party", textarea: true, debug: true });
```

### `stayClose`：浮到外侧时允许拉开的距离

- **测的是什么**：当区域被一个没有内边距的卡片或容器包着，滚动条越过其边框浮到外侧留白里时，与区域拉开的距离就是所越过的边框厚度之和。
- **超过时**：该距离超过此值，就不浮到外侧，而是叠放在内容之上。
- **默认值（12px）**：常见的边框（1px 到 4px）不会触及这个限制。
- **取消限制**：传入 `Infinity`。
- **作用的轴**：纵向、横向都适用。
- **无效值**：负数或非数字的值按默认值处理。
- **误差**：判断是否贴合时允许 1px 的误差，所以在限制值附近可能会有 1px 或 2px 的出入。

### `exclude`：不处理的区域

- **范围**：匹配选择器的元素及**其内部全部**的滚动区域，既不查找，也不处理。
- **外层区域也不会动它**：外层滚动区域不会为了容纳自己的滚动条而缩小该区域的内边距。
- **何时使用**：用来排除无法在标记里加 `data-scrollbar="off"` 的外部组件。
- **多个**：可以用逗号传入多个。
- **错误的选择器**：视为没有传入。

### `debug`：调试显示

在每个处理过的滚动区域上，于页面上层叠加绘制以下内容。

- 按方式区分颜色的边框
- 滚动条所在位置
- 缩小或增加的内边距
- 没有滚动条时内容所在位置
- 标明方式、滚动条粗细、改动值和原因的标签

须知：

- 同样的内容也会写成区域的属性。
- 不会往滚动区域里插入任何东西，不拦截点击，也不影响判定结果。
- 开启期间每一帧都会重新测量各区域的位置，所以只在开发时开启。
- 读法见[问题排查](./troubleshooting.md#问题排查)。

### `quiet`：拦截浏览器提示

- **为什么需要它**：因为在察觉到滚动条出现的当下就修改内边距，浏览器经常产生 `ResizeObserver loop completed with undelivered notifications` 提示。它不影响功能，但会在错误收集工具里堆积。
- **默认（`true`）**：拦截该提示，使它传不到比本库更晚注册的监听器。
- **注意**：**其他代码产生的同样提示也会一并被屏蔽。**
- **关闭**：想亲自看到该提示的话，传入 `false`。

### `textarea`：同时处理文本框

- **默认（`false`）**：不处理文本框，因为它容易与让高度随内容自适应的代码纠缠在一起。
- **开启后**：按与其他滚动区域相同的顺序判定。
- **只能做到两件事**：文本框无法浮出滚动条（它是不能挂 shadow root 的标签）。

| 文本框的状态 | 结果 |
| --- | --- |
| 右内边距不小于滚动条宽度 | 把这段内边距缩小一个滚动条宽度。文字所占宽度不变，所以换行位置不变 |
| 右内边距小于滚动条宽度 | 保持不变。文字会被挤开一个滚动条的宽度 |
| 按 `box-sizing: content-box` 写死了宽度（浏览器默认值） | 保持不变。缩小内边距后文字宽度不会增加，只会让整个框变窄 |
| 加了 `data-scrollbar="manual"` | 接收宽度（`--sbw`）并自行调整 |

- **要让它接得住**：把文本框的左右内边距设为不小于滚动条宽度；宽度写成具体数值的文本框，再加上 `box-sizing: border-box`（大多数 CSS reset 已经这么做了）。
- **文本框的尺寸不会变**：不会改写宽度和高度。
- **作为子元素的文本框同样如此**：没有开启该选项时，即使文本框是另一个滚动区域里撑满宽度的子元素，也不会动它的内边距。
- **始终显示的滚动条保持原样**：`overflow: scroll` 的文本框，其空滚动条不会被隐藏，因为无法察觉文字变化导致的溢出。
- **还原**：关闭该选项或卸载后，恢复为原值。

### 多次安装时

- 使用最后一次安装的选项。
- 把它卸载后，回退到前一次安装的选项。
- 选项变化时，所有正在监视的区域都会重新判定。

## 按区域设置

自动判定不准的区域，在滚动元素上加 `data-scrollbar`。按区域设置的就只有这一个属性。默认不加。

| 值 | 行为 | 何时使用 |
| --- | --- | --- |
| `off` | 把该区域排除在判定和修改之外。纵向、横向都保持原生滚动条 | 本库不该动的区域——自己处理滚动条的组件。无法修改标记的外部组件，用选项 `exclude` 排除 |
| `center` | 即使左右空白不同，也**让它按居中方式（方式 2）判定** | 内容是居中的，但左右空白相差超过 2px，导致自动判定没选中方式 2 的区域 |
| `manual` | **手动控制。** 只把纵向滚动条宽度通过 CSS 变量 `--sbw`、横向滚动条高度通过 `--sbh` 提供出来，不做自动判定。这些值用在哪里、怎么用，由页面代码决定 | 想自己决定内边距、不要自动判定的区域——每一行都有内边距的列表、想单独设定滚动条与内容间距的区域、无法浮出滚动条的列表标签、表格和文本框（文本框需要开启 `textarea` 选项才会收到值） |

```html
<!-- 不处理 -->
<div data-scrollbar="off" style="overflow-y: auto">…</div>

<!-- 固定为方式 2 -->
<div data-scrollbar="center" style="overflow-y: auto">
  <article style="max-width: 720px; margin-left: 40px">…</article>
</div>
```

### `center`：并不会把内容移到中间

- 这个设置是把判定固定为方式 2。
- 它在左侧加上与滚动条等宽的内边距，让本来就居中的内容在滚动条出现后仍留在原位。
- 如果结构不适用方式 2（比如内部没有空白），不会转到方式 3、4，而是什么都不做。
- 如果滚动区域自身的右内边距足够，则优先使用方式 1。

### `manual`：接收滚动条宽度并手动控制

自动判定是“本库自己选”，`manual` 则是“我只告诉你宽度，你自己决定”。

- 加了这个设置的区域，原生滚动条照常显示。本库不做居中、浮到外侧和叠放。
- 本库只做一件事：往该区域写入两个值。
  - `--sbw` 是纵向滚动条的宽度，`--sbh` 是横向滚动条的高度。
  - 有滚动条时是它的粗细（例如 `11px`），没有则为 `0px`。
- 区域内的任何元素都可以通过 `var(--sbw, 0px)`、`var(--sbh, 0px)` 读取这些值。无论是行、页头行还是底部按钮行都可以。

| 想要的效果 | 写法 | 结果 |
| --- | --- | --- |
| 内容不被挤开 | `padding-right: calc(16px - var(--sbw, 0px))` | 内边距缩小一个滚动条宽度，滚动条出现后内容位置不变 |
| 滚动条与内容之间至少保留 8px | `padding-right: max(8px, calc(16px - var(--sbw, 0px)))` | 滚动条再粗也保持 8px 间距。不够的部分会让内容被挤开 |
| 有滚动条时留出更宽裕的内边距 | `padding-right: calc(24px - var(--sbw, 0px))` | 没有滚动条时是 24px，有滚动条时内容与滚动条的间距是 `24px − 滚动条宽度` |
| 让滚动区域外的行与滚动条宽度对齐 | 接收值的元素必须在区域内部 | 区域外的元素收不到值 |

```html
<ul data-scrollbar="manual" style="overflow-y: auto">
  <li style="padding-right: calc(16px - var(--sbw, 0px))">…</li>
</ul>
```

须知：

| 情况 | 内容 |
| --- | --- |
| 要不被挤开 | “右内边距 + 滚动条宽度”必须与有没有滚动条无关、保持相同。上表第一行就是这个式子。写成别的，就会按差值被挤开，这是使用者自己的选择 |
| 内边距比滚动条小时 | 结果会变成负数，该声明被忽略。用 `max(0px, …)` 包起来 |
| 方式 1（自身内边距）优先 | 滚动区域自身的右内边距不小于滚动条宽度时，本库会缩小这段内边距，此时 `--sbw` 为 0 |
| 横向同理 | 滚动区域自身的下内边距不小于滚动条高度时，本库会缩小这段内边距，此时 `--sbh` 为 0。否则通过 `--sbh` 提供高度，也不会浮出横向滚动条 |
| 横向溢出只是由纵向滚动条造成的情况 | `--sbh` 为 0。因为一旦处理了纵向滚动条，这个溢出也会随之消失 |
| 内部还有滚动区域时 | 在内层里会被截断为 0。外层区域的值不会泄漏到内层 |

## 使用建议

### 左右内边距设在同一个元素上，取相同的值

- 像 `padding: 0 16px` 这样写。
- 左内边距设在外层容器上、右内边距设在滚动区域上，看起来一样，判定结果却会不同。

### 不要为滚动条单独加右内边距

- 像 `padding-right: 17px` 这样的值，无法判断是给滚动条留的还是设计上的内边距，本库不会去掉它。
- 滚动条出现时的挤开会被补偿，但没有滚动条时右侧看起来偏宽的问题依然存在。
- 把这个值删掉，就会自动对齐。

### 不要提前预留滚动条位置

- 已预留的位置（`scrollbar-gutter`）在条件允许时会被解除。
- 不过一开始就不预留，结果更确定。

### 如果有自己测量滚动条宽度来修正内边距的脚本，请移除

- 否则两套机制会同时处理同一段内边距。
- 本库隐藏了原生滚动条之后，那个脚本测到的值仍然保留，内边距就会多加一次（测试中确认过左内边距多出了一个滚动条宽度）。
- 无法移除的话，给该区域加上 `data-scrollbar="off"`。
